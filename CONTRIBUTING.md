# Участие в разработке

Сначала выбрать задачу с критериями приёмки и прочитать AGENTS.md. В PR объяснить причину изменения, результат и выполненные проверки. Новые пользовательские сценарии согласовать с ТЗ. Критичные уязвимости не публиковать в открытых issues; до публичного запуска владелец должен назначить приватный контакт для таких сообщений. Внешние материалы сопровождать источником и условиями использования.


Читать docs/README.md и паспорт этапа 24. Указывать результат, затронутые сценарии и выполненные проверки. Приватность проверяет сервер. Документы проверять npm run check:docs; функциональные изменения — npm run verify. Изменение утверждённого дизайна и развёртывание требуют соответствующей задачи владельца.
