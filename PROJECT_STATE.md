## Последняя поставка

- `wr-community-design-stage29.zip`, полный архив исходников с установщиком.
- SHA-256 ZIP вычисляется сборщиком и приводится при выдаче; контрольные суммы содержимого — `SHA256SUMS.txt` внутри ZIP.
- Владелец скачивает ZIP в `/storage/emulated/0/Download`, затем запускает:

```bash
bash "$HOME/wr-deploy/wr-deploy-latest.sh"
```

Помощник выбирает самый высокий номер этапа, проверяет архив и запускает штатный установщик с резервной копией. Следующий выпуск должен иметь новый номер. Пароли и заполненный помощник не хранить в GitHub.

## Возможности и ближайшая задача

Клубы, публикации, комментарии, поиск людей и компании, чаты, профили, игровые события. Турниры: приглашения по логину, личное согласие, пять подтверждённых игроков для новых команд, выход/удаление до старта, сетка на выбывание, результаты и победитель. Старые заявки сохранены по правилам этапа 26. Отмена до старта реализована с причиной и сохранением истории. Редактирование результатов пока не реализовано. [Контракт турниров](docs/TOURNAMENTS.md).

Следующую функциональную задачу определяет владелец. Ограничение состава: повторное приглашение в ту же заявку после отказа/отзыва/выхода не предусмотрено.

## Ограничения

- База оформления — этап 24; компактная мобильная главная — этап 25. Палитру, масштаб 90%, пять нижних разделов, пользовательские изображения и черновики сохранять.
- Основной способ поставки — ZIP + команда Termux. GitHub хранит код и выполняет тяжёлые проверки. Deploy через Actions — отдельно по прямой команде владельца.
- `.github/workflows/vds-deploy.yml` не менять и автоматически не запускать.
- Схема 25 не открывается старым приложением схемы 24. Миграция — только с резервной копией; после публикации не откатывать базу автоматически, теряя новые записи.
- Историю и отдельные изменения `docs/local-pilot-readiness` сохранять. Разработку Android/APK не возобновлять без задачи.

## Как продолжать

Читать [AGENTS.md](AGENTS.md), этот файл и [WORKFLOW.md](docs/WORKFLOW.md); затем только документы и код затронутой области. Не перечитывать всю историю и не повторять уже подтверждённые проверки без новых изменений или ошибок. Обновлять этот файл в том же коммите, что и готовый этап; для документационных правок новый ZIP не нужен.

Сборщик ZIP tools/build-release.py и подготовка публикации tools/prepare-github-tree.py закреплены в этапе 28. Подробная договорённость об ускорении и статус внедрения — в docs/WORKFLOW.md. Не тратить время на повторное чтение и успешные проверки без новой причины.

Исправлена ошибка этапа 28: smoke-проверка ошибочно ожидала 25 новых демо-ботов вместо 24 (25 — общее число аккаунтов с исходным тестовым). Добавлен тест фактического JS-выражения из deploy/smoke-image.sh: миграция холодной копии, повторный seed, передача владения, обработка изображения и неизменность исходной базы. Это локальная проверка выражения, не запуск Docker.
