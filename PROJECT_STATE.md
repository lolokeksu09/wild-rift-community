## Последняя поставка

- `wr-community-design-stage34.zip`, полный архив исходников с установщиком.
- SHA-256 ZIP вычисляется сборщиком и приводится при выдаче; контрольные суммы содержимого — `SHA256SUMS.txt` внутри ZIP.
- Владелец скачивает ZIP в `/storage/emulated/0/Download`, затем запускает:

```bash
bash "$HOME/wr-deploy/wr-deploy-latest.sh"
```

Помощник выбирает самый высокий номер этапа, проверяет архив и запускает штатный установщик с резервной копией. Следующий выпуск должен иметь новый номер. Пароли и заполненный помощник не хранить в GitHub.

## Возможности и ближайшая задача

Клубы, публикации, комментарии, поиск людей и компании, чаты, профили, игровые события. Турниры: приглашения по логину, личное согласие, пять подтверждённых игроков для новых команд, выход/удаление до старта, сетка на выбывание, результаты и победитель. Старые заявки сохранены по правилам этапа 26. Отмена до старта реализована с причиной и сохранением истории. Исправление результатов с причиной и историей реализовано, до завершения следующего матча. Техническое поражение и снятие команды сохраняют состав и историю. «Мои турниры» показывает ближайший матч и победителя. [Контракт турниров](docs/TOURNAMENTS.md).

Капитаны подтверждают готовность обеих команд к назначенному матчу; перенос сбрасывает подтверждения. Организатор назначает и переносит время готовых матчей; участники видят локальное время и уведомления, включая напоминание за 30 минут внутри сайта. Единый центр показывает ответы, события, поиск компании, приглашения и уведомления о матчах с фильтрами и историей. Счётчик объединяет их все; «Прочитать всё» сохраняет новые уведомления за границей снимка и не принимает приглашения. Переходы ведут к конкретным событиям, группам и матчам; открытие страницы не снимает приглашение. Поставка объединяет весь согласованный турнирный блок в один архив. Снятие после старта доступно для команды с определённым соперником в текущем незавершённом матче; капитан или организатор указывают причину. Следующую задачу определяет владелец. Ограничение состава: повторное приглашение в ту же заявку после отказа/отзыва/выхода не предусмотрено.

## Ограничения

- База оформления — этап 24; компактная мобильная главная — этап 25. Палитру, масштаб 90%, пять нижних разделов, пользовательские изображения и черновики сохранять.
- Основной способ поставки — ZIP + команда Termux. GitHub хранит код и выполняет тяжёлые проверки. Deploy через Actions — отдельно по прямой команде владельца.
- `.github/workflows/vds-deploy.yml` не менять и автоматически не запускать.
- Схема 28 не открывается старым приложением схемы 27. Миграция — только с резервной копией; после публикации не откатывать базу автоматически, теряя новые записи.
- Историю и отдельные изменения `docs/local-pilot-readiness` сохранять. Разработку Android/APK не возобновлять без задачи.

## Как продолжать

Читать [AGENTS.md](AGENTS.md), этот файл и [WORKFLOW.md](docs/WORKFLOW.md); затем только документы и код затронутой области. Не перечитывать всю историю и не повторять уже подтверждённые проверки без новых изменений или ошибок. Обновлять этот файл в том же коммите, что и готовый этап; для документационных правок новый ZIP не нужен.

Сборщик ZIP tools/build-release.py и подготовка публикации tools/prepare-github-tree.py закреплены в этапе 28. Подробная договорённость об ускорении и статус внедрения — в docs/WORKFLOW.md. Не тратить время на повторное чтение и успешные проверки без новой причины.
