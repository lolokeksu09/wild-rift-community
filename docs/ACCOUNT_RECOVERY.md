# Резервные коды · 0.24

Владелец выбрал восстановление без почты 03.10.2026. Игрок заранее создаёт восемь одноразовых кодов в «Профиль → Восстановление доступа», подтвердив текущий пароль. Каждый код содержит 128 случайных бит. SQLite хранит только SHA-256; исходники кодов возвращаются один раз и не сохраняются в localStorage/sessionStorage. Секретные ответы не кешируются.

Новый набор отменяет все прежние коды. При потере ответа или уходе со страницы до сохранения нужно создать новый набор с текущим паролем. Автоматический повтор создания отключён. Без сохранённого кода и без пароля самостоятельное восстановление недоступно; подтверждение email не добавлено.

«Профиль → Вход → Забыл пароль?» принимает логин, резервный код и новый пароль (12–128 символов). После проверки кода транзакция удаляет только использованный код, обновляет scrypt-хеш пароля и удаляет все сеансы аккаунта. Новый сеанс автоматически не создаётся; нужно войти с новым паролем. Остальные коды сохраняются. Повтор уже использованного кода возвращает общую ошибку; если ответ потерян, сначала попробовать вход с новым паролем.

## API и защита

С 0.31 доступна отдельная смена пароля с текущим паролем и управление сеансами — [ACCOUNT_SECURITY.md](ACCOUNT_SECURITY.md). Обычная смена атомарно отзывает все старые коды и сеансы, создавая новый сеанс текущего браузера; нужно создать свежий набор кодов. Восстановление по коду сохраняет прежнюю семантику: расходует один код и отзывает сеансы без автоматического входа.

- GET /api/recovery-codes — число оставшихся кодов только своего аккаунта.
- POST /api/recovery-codes — текущий password, действующий сеанс, Origin, маркер запроса и CSRF; максимум пять попыток в минуту на аккаунт. После асинхронной проверки пароля сеанс и актуальный хеш проверяются повторно.
- POST /api/recover — handle, code, password; доступ без сеанса, но с точным Origin и маркером. Общий лимит с входом/регистрацией: 20 запросов в минуту на IP, максимум четыре одновременных вычисления scrypt. При production используется проверенный адрес от прокси. Ошибка не различает отсутствие логина и неверный/использованный код.

Код не работает для другого аккаунта. Одновременное применение одного кода успешно только один раз. Вход с прежним паролем повторно проверяет актуальный хеш после вычисления scrypt, чтобы запрос, начавшийся до восстановления, не создал сеанс после сброса. Авторизованные изменения повторно проверяют сеанс после чтения тела запроса. Содержимое аккаунта не удаляется.

## Миграция и восстановление базы

Схема 18→19 добавляет recovery_codes, без изменения аккаунтов, паролей и содержимого. Существующим игрокам коды не назначаются автоматически. Перед обновлением сохраняется холодная копия; установщик проверяет миграцию на отдельной копии. Старый код схемы 18 не открывает 19; откат требует остановки и отдельного решения о восстановлении, с учётом новых записей.

Восстановление зашифрованной копии отзываёт ВСЕ сеансы и коды: ранее использованный код из старого снимка не должен снова работать. Пароль возвращается к состоянию снимка; пользователям нужно войти с ним и создать новый набор. Холодное ручное восстановление должно выполнить такое же удаление sessions и recovery_codes до открытия доступа.

## Проверки

server/tests/recovery.test.mjs проверяет CSRF/Origin, текущий пароль, ротацию, чужой аккаунт, параллельное применение, повтор, старый/новый пароль, отзыв сеансов, сохранность приватного поста, общий лимит и миграцию. tests/browser-recovery.mjs проходит полный интерфейсный сценарий на 360/390/768/1440 px, проверяет отсутствие кодов в хранилищах браузера и ошибок JavaScript.
