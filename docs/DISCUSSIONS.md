# Обсуждения · 0.16

## Поведение

Под публикацией доступны «Нравится», «Полезно», «Огонь»: один выбор от аккаунта. Нажатие другого заменяет реакцию, повтор выбранного снимает. Реагировать и комментировать могут участники клуба; публичный читатель может сохранить доступный пост. Гостю доступно чтение.

Комментарии показывают последние 50 записей в хронологическом порядке; «Ранее» загружает старые страницы. «Ответить» под исходным комментарием выбирает его для редактора. Под ответом эта кнопка выбирает исходный комментарий ветки; глубина ограничена одним уровнем. Цитата исходного текста помогает понять ответ даже если исходник на другой странице. Отмена ответа сохраняет набранный текст.

@логин (латиница, цифры, подчёркивание; регистр не важен) уведомляет существующего участника этого клуба. Повтор одного логина и совпадение упоминания с адресатом ответа создают одно событие. Максимум 10 уникальных упоминаний; сам автор не получает уведомление. Существование чужого аккаунта не раскрывается отдельным результатом отправки. Это внутренние события; внешние сообщения и push не отправляются.

«Ответы» в верхней панели открывает уведомления, счётчик опрашивается раз в 5 секунд. Открытие обсуждения не отмечает событие прочитанным: есть явная индивидуальная кнопка. В профиле «Сохранённые публикации» открывает личный список от новых к старым; порядок по ID публикации, не по времени сохранения.

## Доступ и повторы

Сервер заново проверяет членство, бан, приватность и блокировки в обоих направлениях. Закрытые посты, сохранённое и события скрываются после выхода/бана. Обе стороны блокировки скрывают посты и комментарии друг друга, кроме персонала клуба: блокировка автором не скрывает от владельца и модераторов его материалы в их клубе (CLUB_MANAGEMENT.md); ответ на скрытый исходный комментарий тоже скрывается. Вложения поста используют ту же проверку. Фильтрация выполняется до LIMIT и счётчика уведомлений. Публичный пост остаётся доступен после обычного выхода из открытого клуба. Сохранение не выдаёт доступ и не делает копию текста.

Записи сохранённого и событий сохраняются при временной потере доступа: при восстановлении законного доступа могут появиться вновь. События не содержат снимков приватного текста; выдача берёт актуальное название поста. Удаление поста каскадно удаляет комментарии, ответы, реакции, сохранения и события. Полученное ранее содержимое нельзя удалить из памяти человека; открытые страницы не используют real-time подписку, изменения контента учитываются при следующей загрузке.

PUT реакций/сохранений и DELETE повторяемы. Комментарии и публикации из текущего интерфейса передают clientId и сохраняют его на форме при сетевой ошибке; повтор одинакового тела возвращает прежний ID, изменение тела с прежним ID — 409. Потеря ответа не создаёт второй комментарий/уведомление. clientId старых клиентов необязателен; для них идемпотентность отправки не гарантируется. Данные форм не записываются в постоянный браузерный кеш. Поздние ответы после смены экрана игнорируются.

## API

Все записи требуют Origin, CSRF, X-Community-Request и сеанс согласно SERVER.md.

| Маршрут | Действие |
|---|---|
| PUT /api/posts/:id/reaction | `{kind:"like"\|"useful"\|"fire"}`; один выбор |
| DELETE /api/posts/:id/reaction | Снять собственную реакцию |
| PUT /api/posts/:id/saved | Сохранить доступную публикацию |
| DELETE /api/posts/:id/saved | Снять сохранение доступной публикации |
| GET /api/saved?before=:postId | Личный список, 20 записей и next |
| GET /api/posts/:id/comments?before=:commentId | Последние 50 доступных комментариев и next |
| POST /api/posts/:id/comments | `{body,clientId?,parentId?}`; родитель из того же поста, только исходный |
| GET /api/discussions/notifications?before=:eventId | Свои доступные события, 20 и next |
| GET /api/discussions/notifications/summary | viewerId и unread |
| POST /api/discussions/notifications/:id/read | Прочтение своего доступного события |

Лента, список постов клуба и конкретный пост содержат reactions, myReaction, saved. POST публикации поддерживает clientId. Полный текст ответа/комментария не включается в событие.

## Миграция и восстановление

SQLite 11→12: nullable client_id у постов/комментариев и parent_id у комментариев; уникальные индексы отправок; post_reactions, saved_posts, discussion_notifications. Старые комментарии остаются исходными. Существующие аккаунты, сеансы, изображения и посты сохраняются. Новый код откажется открывать схему выше 12; старый код версии 0.15 откажется открывать 12.

Установщик принимает 10/11/12, включает 503, останавливает приложение, копирует весь data, проверяет миграцию на отдельной копии, обновляет рабочую базу до 12 и проверяет здоровье до открытия трафика. Ошибка до публикации возвращает прежнюю холодную базу и конфигурацию. После открытия трафика автоматической замены базы нет: новые записи сохраняются до анализа. В CI образ мигрирует холодную схему 11 под непривилегированным пользователем; исходная копия остаётся 11.

`tests/browser-discussions.mjs`: изолированные аккаунты на 360/390/768/1440 px, настоящая потеря ответа после сохранения, повтор без дубля, выбор ответа, уведомления/прочтение/переход, сохранённое и отзыв доступа, экранирование HTML, отсутствие переполнения, скриншоты. Результаты выполнения и фактическая публикация — в PR/Actions. Реальные рабочие аккаунты для тестов не создаются.

Редактирование комментариев, их удаление из интерфейса, реакции на комментарии, поиск по сохранённому и внешние push в этот выпуск не входят.
