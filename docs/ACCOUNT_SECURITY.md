В «Профиль» добавлены обычная смена пароля с текущим паролем и список собственных активных сеансов. Названия устройств, IP и User-Agent сейчас не сохраняются, поэтому интерфейс показывает только срок действия и отметку текущего сеанса. Истёкшие сеансы не выдаются. До 100 строк на страницу, догрузка кнопкой; между запросами список может измениться.

GET `/api/sessions?after=CURSOR` требует сеанс и возвращает viewerId, sessions `{id,expiresAt,current}`, next. ID — отдельная SHA-256-ссылка, построенная из user_id и хеша сеанса с префиксом; это не токен входа и не сохранённый хеш токена. Курсор содержит срок и такую ссылку. Сам токен, хеш токена, CSRF и пароль в списке отсутствуют. DELETE `/api/sessions/:id` требует Origin/CSRF/маркер и ищет только свой активный сеанс. Чужая/отсутствующая ссылка возвращает 404. Ответ содержит ok и loggedOut; для текущего сеанса cookie очищается. Завершение другого сеанса не меняет текущий и не перерисовывает редактор профиля. Действие подтверждается пользователем.

POST `/api/me/password` принимает currentPassword и newPassword (12–128 символов), требует действующий сеанс/Origin/CSRF/маркер. Новый пароль должен отличаться от текущего; интерфейс дополнительно просит повторить его. Максимум 5 попыток в минуту на аккаунт; используется общий предел четырёх одновременных scrypt-операций. После вычисления повторно проверяются актуальные сеанс, CSRF и хеш пароля, затем ещё раз внутри транзакции.

Одна транзакция заменяет scrypt-хеш, удаляет все прежние сеансы и резервные коды и создаёт новый сеанс текущего браузера с новым CSRF. Отзыв старых кодов предотвращает восстановление нового пароля по ранее скопированному коду. Интерфейс объясняет последствия до отправки и после успеха предлагает создать новые коды. Два конкурирующих изменения старого пароля не могут успешно примениться оба. Содержание профиля, клубов, сообщений и публикаций не удаляется. Пароль не сохраняется в браузерных хранилищах или черновиках; после успеха форма очищается. Смена пароля и выход из текущего сеанса предупреждают о несохранённых правках профиля. При потере ответа следует проверить вход с новым паролем, а не автоматически повторять операцию.

Новых таблиц, миграций и зависимостей нет, схема остаётся 20. API и страница аккаунта сохраняют no-store/noindex. Отозванный сеанс перестаёт работать при следующей серверной проверке; уже полученные данные у другого клиента отозвать нельзя.
