# Android-приложение сообщества Wild Rift

Обновлено 05.10.2026 по уточнению владельца. Основной продукт — полноценное Android-приложение с интерфейсом в стиле существующего сайта, современными переходами и анимациями. Подготовка репозитория выполнена; клиент ещё не реализован.

## Решение

Используем Kotlin и Jetpack Compose для нативных экранов. Это технический выбор для реализации поручения; Java не требуется. Kotlin — рекомендованный Google путь для новых Android-приложений, Compose использует Kotlin: [Kotlin-first](https://developer.android.com/kotlin/first), [Compose](https://developer.android.com/compose).

Сохраняем существующий Node.js/SQLite сервер и общие аккаунты. «Сервер как база» означает хранение данных плюс небольшой API с проверками входа и прав. Давать телефону прямой доступ к базе нельзя: пользователь смог бы обходить клубные роли и приватность.

Сайт служит эталоном визуального языка. Android получает собственные экраны, системную кнопку назад, клавиатуру и выбор фото. WebView не входит в выбранный основной путь.

## Данные

| Где | Что хранится |
|---|---|
| Серверная SQLite | Аккаунты, хеши паролей, сеансы, профили, клубы, роли, посты, комментарии, переписка, заявки, жалобы и журнал |
| Та же SQLite, таблица media | Обработанные изображения как BLOB; выдача через серверные проверки |
| Телефон | Настройки, временные данные, черновики и защищённый сеанс своего аккаунта |
| APK | Код, тема, публичный адрес API; без паролей пользователей и секретов оператора |

Сервер — источник истины. Кеш не означает успешную запись. При выходе, смене аккаунта или отказе доступа приватные экраны и данные очищаются. Push и работа без сети требуют отдельной реализации.

## Порядок разработки

Сначала устанавливаемый APK с реальным гостевым сценарием «каталог → клуб → пост». Затем вход, профиль и сеансы; после них вступление, публикации и фото; затем общение, команды, модерация и подготовка выпуска.

Для каждого этапа нужны конкретные состояния экрана, проверка серверных прав и подтверждённая сборка. [Дорожная карта](android/ROADMAP.md) содержит критерии, [статус](android/STATUS.md) — следующую задачу. Название, постоянный applicationId и распространение предстоит определить до релизного подписания.
