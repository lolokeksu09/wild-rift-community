# Дизайн, анимации и доступность

Проектный стандарт 05.10.2026; ещё не реализация экранов. Основа — Compose Material 3 с современными компонентами и выразительными переходами. Использовать стабильные API; experimental Expressive-компоненты брать лишь после проверки зрелости и совместимости: [Material 3](https://developer.android.com/develop/ui/compose/designsystems/material3).

## Визуальный язык

Премиальная тёмная тема сохраняет узнаваемость сайта. Исходные цвета проверены в server/public/premium.css:

| Семантика Android | Цвет |
|---|---|
| Фон | #0c0e12 |
| Поверхность | #14171d |
| Поднятая поверхность | #1c2028 |
| Граница | #2b3039 |
| Основной текст | #f3f0e9 |
| Вторичный текст | #a2a8b3 |
| Основной золотой акцент | #dfc18b |
| Дополнительный лиловый акцент | #b8aacb |

В CSS золотой акцент исторически называется lime; в Android дать ему семантическое имя primary. Не копировать это имя как цвет зелёного. Для каждого интерактивного состояния проверить фактический контраст, включая disabled/error. Светлая палитра — отдельная согласованная таблица до включения переключателя, не инверсия тёмных цветов. Dynamic color не должен неожиданно менять фирменное оформление.

Шаг отступов 4 dp: внешние 16–20, промежутки 8/12/16/24. Скругления: поля 12, карточки 20, модальные поверхности 24 dp — исходные значения для прототипа. Заголовок экрана, заголовок карточки, текст и подпись имеют устойчивую иерархию; системный шрифт и масштаб пользователя. Не размещать важный текст поверх шумной обложки без подложки.

## Компоненты

Единые ClubCard, PostCard, Avatar, EmptyState, ErrorState, SubmitButton, LoadingRow и ConfirmSheet. Карточки отражают настоящие роли, приватность и демо-маркеры. Не показывать вымышленный онлайн или ранги как проверенные.

Четыре основных раздела на телефоне: Главная, Клубы, Сообщения, Профиль. Широкий экран получает rail и, где полезно, список рядом с деталями. Панели учитывают системные отступы; клавиатура не закрывает отправку. Большой текст увеличивает высоту карточки, а не обрезается фиксированным контейнером.

## Карта движения

| Действие | Переход | Ограничение |
|---|---|---|
| Карточка → подробности | Короткий fade/изменение поверхности; shared element для обложки при устойчивом ID | Сохранять позицию списка при возврате |
| Детали → назад | Обратный переход и predictive back | Системный жест определяет направление |
| Открыть фильтры/действия | Bottom sheet с плавным появлением | Фокус и TalkBack перемещаются в панель |
| Фото → просмотр | Увеличение связанного изображения | Не загружать приватный оригинал без права |
| Переключить раздел | Короткий fade; восстановить стек вкладки | Без длинного горизонтального перелистывания |
| Реакция/сохранение | Локальная смена иконки, лёгкое масштабирование | Ошибка возвращает честное состояние |
| Загрузка/отправка | Спокойный индикатор; сохранение текста | Успех только после API |
| Галерея | Ручной pager, счётчик и подпись | Без обязательного автопрокручивания |

Начальные длительности: локальный отклик 120–180 ms, переход 220–300 ms. Это настройки для проверки, не измеренная производительность. Пружины не мешают нажать повторно и не сдвигают читаемый текст. Не анимировать весь список при каждой загрузке.

[Shared elements](https://developer.android.com/develop/ui/compose/animation/shared-elements) и [predictive back](https://developer.android.com/develop/ui/compose/system/predictive-back-setup) включать с поддерживаемыми API. Параллакс, бесконечные блики и тяжёлое размытие не нужны для основного сценария.

## Доступность и приёмка

Учитывать системный масштаб анимаций, включая отключение. При уменьшенном движении — простой короткий fade или мгновенный переход. Кнопки имеют область касания >=48 dp, значимые иконки — подписи, состояния — семантику. Цвет не единственный признак ошибки/роли.

Проверить TalkBack, 200% размер текста, порядок фокуса, landscape, компактный экран, клавиатуру, жест назад и восстановление после поворота. [Compose accessibility](https://developer.android.com/develop/ui/compose/accessibility) — справочник реализации.

Проверка плавности проводится на реальном устройстве: длинная лента с изображениями, переходы и прокрутка. Сначала устранить лишние рекомпозиции/декодирование, затем усложнять движение. Не заявлять 60/120 FPS без измерения.
