# A02 · аккаунт и профиль в Android

05.10.2026. Клиент 0.2.0-preview, versionCode 2. Реализован следующий путь: Профиль → вход/регистрация → изменение профиля → выход. Гостевые клубы остаются доступны. Восстановление по резервному коду, смена пароля, генерация новых кодов и отзыв сеансов используют существующий сервер. Итоги сборки и выпуска — [STATUS.md](STATUS.md).

## Интерфейс

Два работающих раздела: Клубы и Профиль. Логин и имя сохраняются как безопасный ввод; пароль, подтверждение и резервный код остаются только в памяти формы и не попадают в SavedStateHandle. Повторный submit заблокирован, пока запрос выполняется. Мутации не повторяются автоматически после сетевого отказа. Ошибка оставляет форму и объясняет, что результат может быть неизвестен.

Профиль редактирует name, bio, profileVisible и gameProfile.riotId/rank/region/language. Остальные игровые поля сохраняются сервером при частичном обновлении. Эти значения заполняются вручную; подтверждённый Riot ранг не заявляется. Аватар, загрузка фото, роли/чемпионы, блокировки, переписка и запись контента — следующие задачи. Черновик профиля живёт только в памяти формы; после поворота/перезапуска несохранённые изменения пока не восстанавливаются.

После неудачного выхода доступно отдельное действие удаления входа с телефона. Оно явно не обещает отозвать серверный сеанс. Выход со всех устройств, отзыв выбранного сеанса и замена резервных кодов подтверждаются внутри приложения. Сервер возвращает до 100 сеансов; клиент показывает первую страницу и позволяет завершить все, дальнейшая пагинация сеансов остаётся улучшением.

## Сеанс и приватность

`SessionCookies` отправляет только wr_session и только точному HTTPS origin, включая порт. Принимается host-only, Secure, HttpOnly cookie с Path=/, действительным expiry и 64 hex символами. Новое поколение запросов создаётся при очистке: старый ответ не может вернуть cookie после выхода. Никаких redirect, произвольных хостов или отключения TLS. Автоматический повтор соединения отключён, чтобы POST не отправлялся повторно без решения пользователя.

Cookie сохраняется через AES-256/GCM с случайным IV и AAD, ключ создаётся провайдером AndroidKeyStore. В SharedPreferences записывается только шифротекст, не пароль, CSRF или профиль. Повреждённое хранилище удаляется. Backup и перенос данных исключены manifest/xml правилами A01. Используется [Android Keystore](https://developer.android.com/privacy-and-security/keystore); операции ключа выполняются на IO-потоке.

CSRF хранится только в AccountViewModel и заново получается из GET /api/me после запуска/возврата приложения и обновления профиля. Клубные запросы получают текущий cookie. Смена аккаунта, выход и подтверждённый отзыв очищают клуб/пост/комментарии и старый маршрут, отменяют запросы и запускают свежий каталог. Поэтому вход возвращает к каталогу; сохранение выбранного clubId/postId после входа пока не реализовано. 401 скрывает профиль до проверки сеанса; 403 перепроверяет /api/me без автоматического повтора записи. Резервные коды не сохраняются и удаляются при уходе; экран аккаунта закрыт от системных screenshots через FLAG_SECURE.

## Проверки

- JVM-тесты: HTTPS-вход, точные Origin/X-Community-Request/CSRF, профиль, cookie после пересоздания jar, logout; отказ чужому origin/порту/cleartext/domain-cookie и позднему ответу; истёкший cookie; двойной вход; отзыв аккаунта/кодов; очистка старого контента.
- `node tools/check-android-account-contract.mjs`: тот же исполняемый сервер на отдельной in-memory SQLite. Регистрация → профиль → 403 для чужого Origin/CSRF → коды → logout/login → смена пароля → новые коды → logout-all → восстановление → отзыв текущего сеанса. Production не изменяется. Включено в Verify.
- Инструментальные тесты скомпилированы: реальный Keystore/шифротекст/пересоздание/corruption cleanup и Compose-форма вход → сохранение → выход → пустой пароль. Fixture UI не считается проверкой входа на production.
- Проверка этих тестов на устройстве/эмуляторе, TalkBack, API 26 и вход после принудительного завершения процесса ещё требуют фактического запуска. Владелец подтвердил лишь установку/нормальное открытие предыдущего 0.1.0-preview; это не проверка A02.
