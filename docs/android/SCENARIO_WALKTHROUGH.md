# Сверка сайта и Android, 7 октября 2026

Сопоставлены действующие обработчики server/public/app.js, chat.js и серверные маршруты с Android Repository/ViewModel/Compose. Наличие кнопки и правильного API не доказывает выполнение всей формы на устройстве. Итог CI и конкретные количества проверок фиксируются в STATUS после запуска.

| Область | Объём прохода | Новые проверки |
|---|---|---|
| Клубы | Вступление/выход, заявки, настройки, участники, роли, бан, приглашения, передача, закрепления, журнал | JVM: запрет восстановления при бане и смене аккаунта; устройство: каталог и возврат к клубу |
| Публикации | Создание/правка/удаление, реакции, опросы, руководства, черновики, комментарии, поиск, сохранённое | JVM: пустой поиск, параметры фильтров, курсоры, свежие права; HTTPS/UI: старый ответ, собственные и модераторские действия |
| Гостевые команды/события | Публичная allowlist из community-preview; вход с возвратом к выбранному объекту/форме | JVM: открытый preview без защищённых запросов; HTTPS/UI: вход через форму и возврат к группе |
| Состав команды | Заявка, решение владельца, чат только после принятия, выход | HTTPS/UI: заявка и выход; решение и отправка через production ViewModel; API: отзыв чтения |
| События | Места/роли, исключение, отмена, чтение истории без отправки | HTTPS/UI: занятие места; API: исключение, невозможность повторного входа, отмена, права истории |
| Личные сообщения | Запрос/согласие, отправка, история, блокировки, приватность | HTTPS/UI: согласие, отправка, история, блокировка; API: двусторонний запрет. JVM: ограничение аккаунта сохраняет очередь при разрешённом чтении |
| Жалобы | Свои обращения, очередь, решения, санкции, действия удаления, апелляции | HTTPS/UI: решение, апелляция, независимый пересмотр; API: запрет первому модератору и постороннему; JVM: владелец страниц своих жалоб |
| Навигация/уведомления | Нижние вкладки, возврат после входа, нужный комментарий, счётчики и отметки | JVM: маршруты и загрузка старого комментария; HTTPS/UI: возврат к объекту и страницам вкладок |
| Аккаунт | Общий аккаунт, профиль, игровые поля, фото, восстановление, устройства, санкции | Существующие account contract/UI/Keystore проверки; полный ручной проход всех форм не выполнен |

Исправлены: удаление из сохранённого; гостевые анонсы; произвольная подстановка запроса поиска; общие поля разных форм; устаревшие права после пагинации; утрата нужного ответа из уведомления; потеря страницы нижней вкладки; переход после входа; ошибочное удаление очереди при 403 ограничения, когда чтение разрешено.

Тестовый TLS-сервер запускает реальный createApp и временную SQLite-базу схемы 22. Сертификат доверяется только тестовым клиентом, проверка имени хоста сохраняется. Аккаунты, сертификат и metadata создаются на CI перед упаковкой test APK; в выпускаемый APK они не входят. Производственные адрес/аккаунты/данные не меняются.

Не заявлены: ручная приёмка всех действий на физическом телефоне, TalkBack, API 26, перенос фонового push (его нет и у этого клиента), полноценное восстановление всех незавершённых форм после уничтожения процесса. События начинают и завершают серверные часы; отдельного API-кнопки старта/завершения сайт не предоставляет. Жалобы на сообщения чата команд/событий также отключены в текущем веб-клиенте — новый серверный API не придумывался.

Результат первого исполнения: сборка/lint/JVM и полный Verify прошли; из16 инструментальных тестов12 прошли. Новые сценарии команды и события прошли, четыре сценария (контент/личная переписка/модерация/возврат после входа) прерваны тайм-аутом. После исправления синхронизации Compose повторное исполнение блокируется отказом Actions до выделения runner. Матрица выше описывает объём кода/проверок, а не успешное выполнение каждой строки.
