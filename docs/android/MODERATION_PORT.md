# Нативные жалобы и модерация · 07.10.2026

Реализованы Compose-маршруты `moderation/reports`, `moderation/queue`, `moderation/item/ID`, `moderation/report/KIND/TARGET_ID`. Восемь видов жалоб совпадают с [серверной реализацией](../../server/moderation.mjs); `profile` и `club_page` отправляют строковый targetId, остальные — целое положительное число в безопасном диапазоне JavaScript.

Собственные обращения загружаются постранично с сохранением загруженных страниц. Счётчик новых решений берётся из summary при обновлении. Первое решение и результат апелляции отмечаются прочитанными только отдельными кнопками. Одна апелляция с обоснованием 3–1000 символов, отдельные статус и пояснение пересмотра. Ввод остаётся в форме при отказе или потере ответа; автоматического повтора мутаций нет.

Очередь доступна через возвращённый `user.isModerator` и серверный контроль доступа. Фильтр явно относится только к загруженным записям; сервер фильтр не предоставляет. Пересмотр исключает заявителя, автора материала и первоначального модератора. Подтверждение решения и отдельного действия требует явного нажатия в диалоге, пояснение обязательно. Статус санкции автора и серверный срок показываются без локального расчёта санкций.

Поддержаны remove-post, remove-comment, hide-profile, remove-club, close-group, cancel-event, remove-chat-message. Личная переписка модератором не удаляется. Пока апелляция pending, удаление недоступно. Диалог раскрывает последствия конкретного действия, включая удаление всего клуба, отсутствие уведомлений участникам и сохранение снимка/резервных копий. Изменение объекта, повтор с другим текстом и отзыв прав отклоняются сервером.

Снимки показываются обычным выбираемым текстом, без HTML и JSON-дампов. Снимок профиля разбирается в подписи и значения. Переходы к публикациям, клубам, профилям, группам и событиям используют существующие маршруты и последующую проверку доступа соответствующим Repository. Для сообщений и комментариев API очереди не возвращает conversationId/clubId/postId: переход не придумывается. После применённого действия переход к удалённому объекту скрывается.

## Ограничения и проверки

API не имеет GET отдельного обращения: подробный маршрут ищет ID по доступным страницам собственного списка и, только при возвращённом праве модератора, очереди. Не добавлены серверные маршруты или изменения данных. Доступ к снимку отсутствует в собственном списке по действующему контракту. Автоматический пятисекундный web-счётчик заменён обновлением при открытии/действии и явной кнопкой; push отсутствует на сервере. Черновики сохраняются Compose saveable в пределах жизненного цикла экрана, постоянного хранения черновиков жалоб нет.

ModerationContractTest проверяет все виды и типы ID, независимость пересмотра, запрет удаления при pending appeal, текстовый снимок, последствия удаления, точные GET-пути и курсоры. Попытка `testDebugUnitTest --tests ru.wrcommunity.android.ModerationContractTest` остановилась до компиляции: Gradle 8.14.3 не удалось скачать (`Network is unreachable`). `git diff --check` прошёл. Сборка/исполнение JVM-проверок и проверка TalkBack/200% текста/реального устройства должны быть подтверждены общим прогоном Android; наличие исходников не является доказательством выполнения сценария.
