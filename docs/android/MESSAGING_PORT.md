# Нативная переписка

Compose-клиент использует существующие серверные API без WebView. Входящие/отправленные/отклонённые запросы, страницы бесед и общие счётчики, создание первого сообщения, согласие получателя, приватность новых запросов, список блокировок и снятие блокировки реализованы отдельным MessagingViewModel.

Личные и клубные комнаты читают историю по 50 сообщений; ранняя история загружается кнопкой, новые страницы догружаются последовательно при опросе. Ручное обновление заново читает весь уже загруженный диапазон от последней страницы до прежней ранней границы и заменяет историю, убирая удалённые сообщения. Опрос работает каждые 2 секунды только для открытой комнаты при STARTED lifecycle. Список получает счётчики каждые 5 секунд с увеличением паузы при ошибках до 60 секунд. Отметка прочтения доступна только личным беседам: API для клубного прочтения отсутствует. Смена blockVersion очищает клубную историю и загружает актуальную страницу; меньшая версия отвергается. Подтверждение отправки не двигает входящий курсор.

Черновики и очередь до 20 неподтверждённых сообщений разделены по аккаунту и комнате. В Android они сохраняются между перезапусками процесса в AES-GCM хранилище с ключом AndroidKeyStore; backup и перенос устройства выключены. Текст, маршруты комнат, аккаунт и clientId находятся внутри шифротекста. История сервера на диск не сохраняется. Очередь и черновик открытой комнаты показываются только после новой успешной проверки её доступа сервером; при потере связи до проверки они остаются скрыты. Отказ доступа удаляет данные комнаты, выход/отзыв сеанса/смена аккаунта очищают хранилище. Начальная загрузка гостевого состояния до восстановления сеанса сохранённую очередь не удаляет. Успех первого запроса очищает только неизменённый отправленный черновик: новый ввод во время ожидания сохраняется. Повтор происходит только по явному нажатию и сохраняет clientId и исходный текст. Удаление очереди подтверждается с предупреждением, что доставленная запись не удаляется. Отклонение запроса и блокировка требуют подтверждения. Жалобы передают точные серверные виды club/direct через раздел модерации. Ошибки доступа очищают приватный контент.

История прокручивается отдельно; поле сообщения закреплено внизу с отступом клавиатуры. Собственные и чужие сообщения различаются расположением и оформлением, профиль/жалоба/блокировка доступны в меню сообщения. Входящие показывают компактные строки с буквенными аватарами: текущий API бесед и чатов не возвращает идентификаторы фотографий. Первое сообщение создаётся через отдельный диалог, не перед списком бесед.

Ограничения: сохранение черновика выполняется на IO после изменения ввода; внезапное завершение процесса до записи последнего изменения может его потерять. Перед отправкой очередь сохраняется, автоматического повтора нет. Счётчики и комнаты используют HTTP-опрос, push отсутствует на сервере. Реальная установка, TalkBack, крупный текст и сценарии отзыва доступа на устройстве требуют отдельной проверки. Контрактные JVM-тесты покрывают парсинг страниц, общие счётчики, бюджет, маршруты и идентификатор повторной отправки. Дополнительные ViewModel-тесты проверяют скрытую очередь до ACL, отказ/временную ошибку, восстановление и согласование clientId, повтор исходного текста, очистку и смену комнаты. MessageStorageTest проверяет настоящий Keystore, шифротекст, новое хранилище, изоляцию аккаунтов/комнат и повреждение записи. Добавление тестов не означает их успешное выполнение; фактические результаты — в STATUS и Android CI.
