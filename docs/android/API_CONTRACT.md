# Контракт начального Android API

Проверка исходников 05.10.2026, серверный код 0.31, схема 22. Это описание начальных сценариев, **не полный OpenAPI и не проверка запросов из Android**. Адрес API задаётся конфигурацией сборки; не отключать TLS-проверку.

Источники: [app.mjs](../../server/app.mjs), [catalog.mjs](../../server/catalog.mjs), [clubs.mjs](../../server/clubs.mjs), [discussions.mjs](../../server/discussions.mjs), [profiles.mjs](../../server/profiles.mjs), [media.mjs](../../server/media.mjs). DTO и минимальные response fixtures закрепить на A01 после чтения конкретных обработчиков.

## Гостевой этап

| Метод/путь | Параметры и ответ | Доступ |
|---|---|---|
| GET /api/me | user: объект или null; csrf: строка или null | Гость допустим |
| GET /api/clubs | q <=100, tag <=40, scope=all/open/mine, sort=new/name/discussion, after; ответ viewerId,total,tags,clubs,next | mine требует входа |
| GET /api/clubs/:id/detail | club: описание/членство/роль, transfer: разрешённая заявка или null | Закрытый клуб не раскрывает приватные посты |
| GET /api/clubs/:id/posts | before числовой; ответ posts,next | Право чтения клуба |
| GET /api/posts/:id/comments | before; viewerId,comments,next; до 50 комментариев, порядок внутри страницы от старых к новым | Право чтения поста |
| GET /api/feed | before числовой; posts,next | Фильтрация по правам/блокировкам |
| GET /api/media/:id | Бинарное изображение | Проверяется доступ к вложению |

GET /api/posts/:id существует в app.mjs и возвращает {post: объект} после postFor-проверки доступа. Использовать его для прямого открытия выбранной публикации.

Клубы возвращают snake_case поля, включая owner_id/created_at/cover_id, и вычисленные membership/myRole/isDemoClub. User имеет camelCase, например avatarId/profileVisible/gameProfile. id пользователя/клуба — строка UUID, id поста — число. next бывает числовым либо непрозрачным строковым курсором в зависимости от маршрута; null завершает список. Не считать длину страницы единственным признаком конца.

## Авторизация A02

Существующий вход: POST /api/register (handle,name,password), POST /api/login (handle,password). Результат user+csrf и Set-Cookie wr_session. GET /api/me восстанавливает состояние текущего сеанса.

Мутации проверяют точный Origin и X-Community-Request: 1; для авторизованных мутаций также X-CSRF-Token. У cookie HttpOnly/SameSite=Strict и Secure в production. Нативный HTTP-клиент должен иметь явный cookie jar и согласованное правило отправки только своему origin. Наличие нужных заголовков не является доверенной идентичностью.

На A02 интеграционно проверить cookies, Origin/CSRF, повторный запуск, выход и отзыв. Не отключать текущие защиты и не вводить JWT без необходимости. Сохранение сеанса и backup-исключения проверить отдельно.

| Маршрут | Назначение |
|---|---|
| POST /api/logout | Выход из текущего сеанса |
| POST /api/logout-all | Отзыв всех |
| GET /api/sessions | Свои сеансы, next/after |
| DELETE /api/sessions/:id | Отзыв своего сеанса; id не bearer-токен |
| POST /api/me/password | currentPassword,newPassword; ротация сеанса |
| GET/POST /api/recovery-codes | GET: remaining; POST: password текущего аккаунта, ответ codes |
| POST /api/recover | handle,code,password (новый пароль); ответ {ok:true}, затем обычный вход |

## Файлы и повтор отправки

POST /api/media принимает **сырые байты**, не multipart; X-Upload-ID из 16–80 символов [-a-zA-Z0-9_]. JPEG/PNG/WebP до 5 MiB, до 16 миллионов пикселей. Сервер нормализует через Sharp: <=1600 px, WebP <=1 MiB, без ненужных метаданных. Хранение — media BLOB в SQLite. Content-Type должен соответствовать фактическим байтам. Ответ: image {id,width,height,size}, replayed; конфликт X-Upload-ID с другим файлом даёт 409. Серверные квоты: 50 MiB на владельца и 500 MiB суммарно.

Посты/комментарии/сообщения имеют маршрутные механизмы clientId. Один пользовательский submit получает устойчивый ID; повтор после потери ответа использует тот же ID и payload. Нет общей гарантии идемпотентности всех POST: регистрацию, пароль, решения и другие операции не повторять автоматически по аналогии. Для каждой мутации проверить дубликат, конфликт payload и доступ после отзыва.

## Ошибки и совместимость

Типичная ошибка — JSON {error: строка}. Для загрузки также учитывать 413 (размер) и 415 (тип файла). Обрабатывать статус отдельно: 401 вход, 403 права, 404 недоступная цель, 405 метод, 409 конфликт повторного ID, 422 ввод, 429 лимит, 500 временная ошибка. Ответы лимитов могут иметь дополнительные поля/заголовки: использовать только фактический контракт конкретного маршрута. Не показывать stack trace, секреты или сырые исключения.

GET можно повторить ограниченно с backoff; отменять при уходе со страницы. Мутации повторять лишь по описанному контракту. Проверить таймаут, потерю ответа, пустой/невалидный JSON, дубли страниц и смену аккаунта во время запроса.

Уведомления сейчас доступны через /api/notifications/summary и опрос. Это не Android push. Полные контракты личных сообщений/объявлений/модерации добавляются в рамках соответствующего этапа, с серверными тестами и поддержкой уже установленного клиента.

## Совместимость с main · 07.10.2026

Текущая схема сервера — 22; Android не открывает SQLite напрямую. `GET /api/me` дополнительно возвращает `sanction: {level, violations, until} | null`. Поля level — `warning`, `restricted`, `suspended`; until — срок в миллисекундах Unix либо null для предупреждения. При приостановке сеансы отзываются, cookie сбрасывается: `/api/me` возвращает user=null, защищённые запросы — 401, вход — 403 с текстом «Аккаунт приостановлен до …». На 401 очищать локальную идентичность/приватный контент; на 403 сохранять форму и показывать серверное объяснение, не повторять запись автоматически. Ограничение не запрещает чтение, жалобы, выход и блокировки. Поиск и каталоги с q могут возвращать 429; сохранять запрос и предлагать повтор позже.

`GET /api/posts/:id/comments` содержит clubId и canModerate; новый `DELETE /api/clubs/:id/comments/:commentId` доступен владельцу/модератору своего клуба. В жалобах добавлены lfg, event, club_page; targetId для club_page и profile — строка, для остальных — числовой ID. Блокировка в любую сторону не запрещает жалобу. В очереди модерации senderSanction; действия remove-club, close-group, cancel-event, remove-chat-message добавлены к `POST /api/moderation/reports/:id/action`. Эти возможности не означают наличие Android-экранов модерации.
