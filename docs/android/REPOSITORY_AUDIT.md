# Аудит подготовки репозитория

Дата 05.10.2026. Анализ локального кода и документов, не нагрузочный тест и не повторная проверка production.

## Проверенные факты

- package.json: сервер 0.31.0, Node >=24.19.0 <25, единственная runtime-зависимость Sharp 0.35.5.
- HTTP: server/app.mjs и тематические модули; SQLite и миграции в server/database.mjs; текущая схема 20.
- server/public/ — работающий web-клиент; Docker копирует server/, тесты используют текущие пути.
- Вход рассчитан на cookie/Origin/CSRF. Полноценного mobile/versioned API-контракта пока нет.
- Изображения хранятся в SQLite BLOB. Размер и права проверяются сервером.
- На момент A00 Android Gradle-проекта и APK не было. Позже в A01 созданы исходники и debug APK; актуальные проверки — [STATUS](STATUS.md). Исходно обнаруженные JDK 17 и SDK/adb использованы для сборки.
- Прежние ARCHITECTURE/SERVER/ROADMAP описывали ранние версии и противоречили коду 0.31.
- docs/prototype.html читается существующим DOM-тестом; его удаление сломало бы проверку.

## Что упорядочено

Вводные документы актуализированы; прежние снимки сохранены в docs/history/. Android-документы собраны в docs/android/, добавлены android/README и локальные инструкции, шаблон задачи и проверка Markdown-ссылок. Версия сервера не повышается ради документов.

Не переносить server/public, миграции, fixtures и deploy косметически. «Чистый репозиторий» означает понятные точки входа и отделённую историю, а не удаление работающего клиента или пользовательской базы.

## Риски и очередность

| Риск | Решение / этап |
|---|---|
| Нет воспроизводимой Android-сборки | Stable матрица и Wrapper на A01 |
| Реальный TLS/JSON из APK не проверен | Гостевые запросы на A01, без trust-all |
| Cookie-сеанс и backup телефона | Проверить и закрепить механизм на A02 |
| Утечка кеша при смене аккаунта | Account-scoped данные, отмена старых запросов, тест позднего ответа на A02 |
| Дубли после потери ответа | Для каждой мутации проверить clientId и конфликт payload на A03/A04 |
| Приватный контент после отзыва | Перепроверка сервером, очистка UI/кеша на 401/403/404 |
| Изменение API ломает установленный клиент | Контракт/fixtures и совместимость при каждом API-изменении |
| Все экраны в одном огромном модуле UI | Feature-пакеты и Repository; делить Gradle лишь по необходимости |
| Тяжёлое движение и изображения | Размеры/кеш по правам, профилирование реального устройства A07 |
| Нет независимой копии | Отдельная эксплуатационная задача до широкого запуска |
| Нет постоянной подписи/политики данных | A08; отдельно подтвердить обновление и удаление/экспорт аккаунта |

## Границы анализа

Не измерены нагрузка SQLite, FPS, Android память и доставка push. Проверки браузера не заменяют эти измерения. Сервер не переписывается и PostgreSQL не добавляется без обоснования.

Подготовка не меняет пользователей, демо-клубы, сообщения, схему, безопасность и конфигурацию deployment. Дальнейшая работа начинается с [A01](STATUS.md), а не с одновременного переписывания всего продукта.
