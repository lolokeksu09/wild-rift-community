## Изменения

- Жалобы на доступные чужие публикации, комментарии и опубликованные профили. Сервер повторно проверяет членство, бан, двусторонние блокировки и публичность. Повтор одной жалобы возвращает прежний ID. Сохраняется снимок текста; скрытый Riot ID, пароль и сеансы в него не попадают. Изображения отдельным снимком не сохраняются.
- В очереди сохраняются прежние правила независимого решения и апелляции. После окончательного подтверждения нарушения независимый модератор может отдельно удалить публикацию с обсуждением, удалить комментарий с сохранением ответов без цитаты либо скрыть текущий публичный профиль. Действие имеет подтверждение, пояснение и отдельную запись журнала; одинаковый повтор не выполняет его второй раз. Изменившийся после жалобы текст не удаляется по старому снимку. Удаление не отменяется апелляцией; скрытие профиля не блокирует аккаунт и не запрещает повторную публикацию профиля. Автоматических банов нет.
- Профиль предупреждает о несохранённом тексте, выборе видимости/ролей, селектах и выбранных файлах при переходе, назад/вперёд и закрытии страницы. Отказ сохраняет текущую форму. Автоматического черновика профиля нет; предупреждение при закрытии зависит от браузера.
- `/api/clubs` выполняет поиск и фильтры на сервере до ограничения страницы. Параметры: `q`, `tag`, `scope=all|open|mine`, `sort=new|name|discussion`, `after`. Ответ: `clubs`, `total`, `tags`, `next`, `viewerId`. По 100 записей, курсор по значению сортировки и ID. По названию применяется нормализованный порядок с кириллицей перед прочими названиями. Сортировка обсуждений не раскрывает время недоступных публикаций. «Мои клубы» отдельно догружает все текущие членства, даже если их нет на первой странице каталога. При изменении поля сортировки между запросами состав страниц может измениться; это не фиксированный снимок каталога.
- `/api/direct` выдаёт страницы по 50 бесед с `next`; счётчики относятся ко всем доступным беседам. Подсчёт страницы выполняется одной SQL-выдачей, без отдельного вызова SQLite для каждой беседы. `/api/direct/summary` возвращает только счётчики, без тел сообщений.
- `/api/notifications/summary` объединяет пять счётчиков в один HTTP-ответ. Видимая вкладка обновляется раз в 5–30 секунд, ошибки увеличивают интервал до 60 секунд, скрытая вкладка прекращает фоновые запросы счётчиков и возобновляет их при возвращении. Запрос уже в полёте может завершиться. Открытый чат сохраняет существующий опрос раз в 2 секунды; нагрузочный предел не измерен.
- Публичные JS/CSS получают хеш содержимого в URL и длительный immutable-кеш только при совпадении хеша. HTML, API, приватные файлы и неверсированные запросы сохраняют `no-store`. В конфигурации Caddy включено `encode zstd gzip`; gzip подтверждён на живом сервере.
- Страница публикации получает H1; публичный профиль выделяет раздел «Люди». CI всегда выполняет весь браузерный набор, включая новые проверки, без предположения об успешном родительском коммите.

## База и восстановление

Схема SQLite 19 → 20 перестраивает таблицу жалоб с новым перечнем объектов и строковым `target_id`, сохраняя старые ID, снимки, решения, прочтение, ссылки апелляций и журнала и счётчик AUTOINCREMENT. Добавляет журнал фактических действий и индексы. Проверка внешних ключей выполняется до фиксации; ошибка откатывает транзакцию.

Перед production-обновлением: обслуживание и холодная копия базы, проверка миграции на копии, затем штатное развёртывание и smoke-проверки. Старое приложение не открывает схему 20. До открытия трафика возможен возврат прежнего образа и холодной базы; после открытия нельзя заменять базу старой копией с потерей новых записей. Инструменты зашифрованного резервирования поддерживают копии схем 19 и 20 и возвращают фактическую схему. Внешнее назначение и расписание не активированы.

## Живой владелец демонстрационных клубов

Пользователь выбрал существующий аккаунт `lolokeksu`. Операторский инструмент не назначает владельца через публичный API и не позволяет участникам захватывать клубы.

Предварительная проверка на сервере новой версии:

```bash
node server/demo-ownership-cli.mjs /data/community.sqlite lolokeksu
```

Применение в отдельном окне обслуживания после проверки вывода:

```bash
node server/demo-ownership-cli.mjs /data/community.sqlite lolokeksu --apply /data/before-demo-ownership.sqlite
```

Путь копии должен быть новым. Команда создаёт согласованный SQLite backup и проверяет целостность до изменения. Все шесть известных демо-клубов и реальный аккаунт проверяются повторно внутри транзакции. Чужое живое владение, отсутствующий клуб или бан выбранного владельца останавливают весь пакет. Назначение включает членство, отзыв старых приглашений, отмену ожидающих передач и журнал каждого клуба; повтор не создаёт новые записи. Демо-метки материалов и клубов сохраняются, вход ботам остаётся запрещён. При аварии до открытия трафика использовать проверенную копию, после открытия сохранить новые записи до разбора.

Процедура проверена на временной базе и применена к production штатным установщиком, результат подтверждён выше. Повторный seed после передачи по-прежнему останавливается при изменившемся владельце и не должен запускаться.
