# Ручная диагностика VDS

Workflow `.github/workflows/vds-readonly.yml` выполняет чтение через GitHub runner, у которого есть сетевой доступ к VDS. Прямой SSH из среды чата не требуется.

## Запуск

GitHub → Actions → **VDS status, logs and application archive** → **Run workflow**. Выбрать ветку `main` и операцию:

| Операция | Результат |
| --- | --- |
| status | UTC-время, установленный SHA, состояние контейнеров и HTTPS-проверка |
| logs | Последние 80 строк служебных логов app и Caddy |
| archive | Исходники запущенного приложения: server/, package.json и package-lock.json |
| snapshot | Все три операции; выбран по умолчанию |

После успешного задания скачать artifact `vds-readonly-<run_id>`. В нём находятся только результаты выбранных операций. Архив сопровождается перечнем файлов и SHA256SUMS. Срок хранения артефакта — три дня.

## Границы доступа

Секрет `vvd_ssh_wr` используется только во временном каталоге runner и удаляется при завершении шага. Его публичная часть проверяется; ключ хоста закреплён. Workflow доступен только для ручного запуска из main, не исполняет произвольные команды из полей ввода и не использует код PR.

Операции не останавливают контейнеры, не развёртывают релизы и не изменяют конфигурацию или базу. SQLite, .env, SSH-ключи, резервные копии и node_modules не входят в архив. Логи сохраняются в артефакт; при добавлении новых логгеров нужно проверять, что они не содержат приватный контент или секреты. Текущий app пишет адрес запуска и коды ошибок, Caddy — служебные сообщения без включённого access log.

Это выполнение отдельных заданий, а не интерактивный SSH-сеанс. Успешный Verify для интерфейса и боевой deploy остаются отдельными проверками и действиями.
