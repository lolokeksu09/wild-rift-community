# Этап 35 — управление составом турнирной команды

Повторные приглашения после отказа, выхода, удаления и отзыва; новое согласие для каждого повторного приглашения. Статусы и приватная история состава с пагинацией. Готовность пяти участников и причины неготовности перед стартом. Повторы после потери ответа не создают новые приглашения; старые ответы не изменяют новое приглашение.

SQLite 29: отдельная таблица истории, существующие команды, приглашения, результаты и пользовательские данные сохраняются. Установщик предварительно мигрирует холодную копию и сохраняет резервную копию. Не откатывать только приложение на схему 28.

Проверки: целевые серверные сценарии и реальный HTTP DOM повторных приглашений прошли; полный verify прошёл: 148 серверных тестов и весь включённый DOM-набор. Проверены миграция 28→29, повторное открытие, приватность и пагинация истории, устаревшие запросы, потеря ответа и готовность команды. Docker и браузерный набор — в GitHub Actions. Для Actions добавлен сценарий нового состава на 320/390/1440 px. Локальный Chromium отсутствует. Установка на VDS и реальный телефон не подтверждены; deploy не запускался.
