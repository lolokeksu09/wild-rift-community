# Развитие клубов · 0.17

## Интерфейс

Публичная карточка клуба показывает метки. Внутри — обложка, один из четырёх акцентов, роль пользователя, правила в раскрываемом блоке. Правила/метки/описание публичны также в клубе по заявкам; приватные посты и чат не раскрываются.

Вкладки: «Посты» с компактным списком до трёх закреплённых публикаций и раскрываемым редактором «Написать публикацию»; «Чат» с существующим контроллером; «Участники»; для владельца «Управление». Чат создаётся только на активной вкладке, при уходе опрос прекращается. Список участников догружается страницами; участнику показываются только принятые, руководителям также заявки/баны. Владелец назначает/снимает модераторов из списка.

Управление содержит редактирование имени, описания, правил, до пяти меток, акцента и обложки, приглашения и журнал. Режим вступления не меняется в этом выпуске. Версия настроек защищает от перезаписи чужих изменений: устаревшее сохранение получает 409 и требует обновления.

## Права

| Действие | Владелец | Модератор клуба | Участник |
|---|---|---|---|
| Приватное чтение, пост/комментарий, чат | Да | Да | Да |
| Принять/отклонить заявку | Да | Да | Нет |
| Исключить/заблокировать обычного участника | Да | Да | Нет |
| Снять бан | Да | Нет | Нет |
| Закрепить/удалить публикацию | Да | Да | Только удаление собственной |
| Настройки/обложка/роли/приглашения | Да | Нет | Нет |
| Предложить передачу владения | Да | Нет | Нет |
| Принять предложение передачи | Только указанный принятый участник | Только указанный принятый участник | Только указанный принятый участник |
| Журнал управления | Да | Да | Нет |

Права проверяются сервером после чтения запроса, в контексте конкретного клуба. Роль не назначает модератора платформы. Выход удаляет роль; снятие полномочий действует на следующий запрос. Нельзя санкционировать владельца. Для санкции против модератора владелец сначала снимает роль. Исключение позволяет подать новую заявку; бан не удаляется через leave/join. Снятие бана удаляет запрет, затем игрок вступает обычным способом.

Закрепления проверяют принадлежность поста клубу, доступ и блокировки. Максимум три на весь клуб; повтор PUT/DELETE не создаёт новый закреп или запись журнала. Блокировки и приватность учитываются также при чтении закреплённого. Удаление поста удаляет закрепление и связанные обсуждения/изображение по прежним правилам. Перед удалением интерфейс предупреждает о последствиях.

## Приглашения

Только владелец: срок 1–168 часов, 1–50 использований, максимум 10 неотозванных неистёкших ссылок. Интерфейс предлагает 24/72/168 часов. После создания форма показывает ссылку для самостоятельного копирования; сообщения внешним людям автоматически не отправляются.

Ссылка `/#invite=<token>` использует fragment, который не передаётся в HTTP URL. Клиент удаляет его из адресной строки и хранит только в памяти на время входа/регистрации. Проверка/вступление передают token в JSON-теле. SQLite содержит только SHA256 token; список приглашений не содержит token или URL. Вновь получить исходную ссылку из истории нельзя. Повтор создания с тем же clientId в том же сеансе возвращает ту же ссылку; изменённые параметры/сеанс — 409. Текущий CSRF служит ключом HMAC-SHA256; clientId не является секретом.

Приглашение не даёт приватного чтения: в закрытом клубе создаётся pending-заявка, в открытом — member. Бан и блокировки с владельцем/создателем запрещают использование. Просмотр не расходует лимит. Новое членство, запись использования, счётчик и журнал сохраняются в одной транзакции. Две попытки на последнее использование дают один успех. Повтор принятия с существующим членством не увеличивает счётчик. Каждый аккаунт использует одну ссылку один раз; после выхода повтор по тому же token не возвращает бесплатное членство. Обычное вступление через карточку остаётся доступным по правилам клуба.

Отзыв/истечение закрывают дальнейшее использование, сохраняя уже принятое членство и прежние заявки. История управления показывает последние 50 приглашений с числом использований, сроком и отзывом. Token и приватный контент в журнал не записываются.

## Передача владения

Владелец выбирает другого принятого участника. Предложение действует 24 часа, одно активное на клуб. Пока получатель не согласился, владелец сохраняет полномочия. Получатель видит предложение внутри клуба, может принять или отклонить; владелец может отменить. Перед согласием проверяются актуальное членство, срок, статус предложения и текущий владелец. Устаревшее предложение не может сменить нового владельца.

Принятие атомарно меняет owner_id, увеличивает версию настроек, снимает роли модератора у передающей пары, отзывает все прежние приглашения и пишет журнал. Бывший владелец остаётся обычным участником; другие модераторы остаются. Повтор согласия ничего не меняет. Новый владелец не может выйти, пока не передаст владение. Предложения не отправляются внешними сообщениями или push; получатель увидит их при открытии клуба.

## API

Новые/расширенные маршруты; записи требуют сеанс, Origin, CSRF и X-Community-Request.

| Маршрут | Назначение |
|---|---|
| GET /api/clubs/:id/detail | Публичные сведения, своё членство/роль, своё предложение передачи |
| PATCH /api/clubs/:id/settings | `{version,name?,description?,rules?,tags?,accent?}`; владелец |
| GET /api/clubs/:id/members?after=:handle | 100 записей/next; активный участник, выдача по роли |
| PUT / DELETE /api/clubs/:id/moderators | `{userId}`; владелец |

| POST /api/clubs/:id/ban / kick / unban | `{userId}`; руководитель, unban только владелец |
| GET /api/clubs/:id/pins | Доступные закреплённые посты |
| PUT / DELETE /api/clubs/:id/pins/:postId | Закрепить/снять; руководитель |
| DELETE /api/clubs/:id/posts/:postId | Удаление с журналом; руководитель |

## Миграция и проверки

SQLite 12→13 добавляет правила/метки/акцент/версию настроек, club_moderators, club_pins, club_invites, club_invite_uses, club_transfers и индексы. Существующие владельцы и членство сохраняются; модераторы автоматически не назначаются. Старые посты, чаты, обсуждения, медиа и сеансы сохраняются. Код 0.16 не откроет схему 13.

Установщик принимает 10/11/12/13, включает обслуживание 503, сохраняет холодный data, проверяет переход на отдельной копии, мигрирует рабочую базу до 13 и проверяет приложение перед публикацией. Откат холодной копии возможен только до открытия трафика. После публикации новые записи сохраняются до анализа сбоя. Docker smoke воспроизводит холодную 12→13 под пользователем node, проверяет целостность/медиа и неизменность исходной схемы.

`server/tests/clubs.test.mjs`: миграция/копия/повтор, настройки и устаревшая версия, отдельные роли/чужой клуб, предел закреплений и журнал повторов, модерация, отзыв/выход, приглашения/хеш/бан/блокировки/срок/последнее использование, передача/согласие/отмена/срок/смена полномочий/перезапуск.

`tests/browser-clubs.mjs`: 360/390/768/1440 px, формы правил/меток/акцента, назначение роли, fragment-ссылка → регистрация → заявка без доступа к постам, принятие модератором, закрепление/чат, согласие нового владельца и отзыв ссылки, журнал, экранирование и переполнение, скриншоты. Реальные рабочие аккаунты не используются. Результаты конкретного CI/публикации — PR/Actions.

Ограничения: нет скрытых клубов, редактирования режима вступления, модерации комментариев, внешних уведомлений о передаче или подтверждённого нагрузочного испытания.
