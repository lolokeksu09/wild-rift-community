# Закрытый пилот: подготовка и ограничения

Дата: 30.09.2026. Статус: регламент подготовлен; сессия с реальными участниками не проводилась. TASK-16 остаётся открытой.

## Что можно провести сейчас

Локальную модерируемую сессию на одном компьютере. Каждый аккаунт работает в отдельном профиле браузера; вкладки одного профиля делят cookie и не изображают разных пользователей. Обычное и приватное окно дают два сеанса; для остальных нужны отдельные профили. Участники могут по очереди выполнять задания на этом компьютере. Это проверка удобства, а не удалённый пилот или замер удержания.

Сервер слушает только 127.0.0.1; адрес с телефона откроет сам телефон, а не компьютер. Не менять привязку, не открывать порт и не использовать туннель как замену подготовке публичного сервера. NODE_ENV=production пока запрещён кодом.

## Подготовка оператора

1. Выбрать компьютер с Node 24.19.0 из ветки 24.x и браузером. Зафиксировать commit, ОС и версию браузера в отчёте.
2. Назначить ведущего сессии и человека, принимающего замечания. Не считать их назначенными этим документом.
3. Использовать только тестовые аккаунты, вымышленные сообщения и отдельные пароли; не вводить пароль Riot, платёжные или иные чувствительные данные.
4. Для нового локального пилота выделен отдельный путь data/pilot/community.sqlite, отличный от стандартной базы. Если он уже существует, это продолжение прошлой сессии: до запуска сохранить копию по BACKUP.md, не удалять её ради чистого старта.
5. Выполнить из корня репозитория в bash:

```bash
npm ci --prefix tests
npm run verify
COMMUNITY_DB=data/pilot/community.sqlite PORT=3000 npm start
```

Открыть http://127.0.0.1:3000 на том же компьютере. При занятом порте выбрать свободный и записать его; не завершать чужие процессы. Остановка — Ctrl+C в терминале сервера. Повтор команды продолжает работу с той же базой; не запускает сброс данных.

Браузерные автотесты отдельно: `node tests/node_modules/playwright/cli.js install chromium`, затем `npm run test:browser --prefix tests`. Отсутствующий браузер или неуспешная проверка записываются как блокировка, а не PASS.

## Аккаунты и права

Для основной сессии: владелец клуба, участник и посторонний. Для жалоб и независимой апелляции — ещё два отдельных аккаунта модераторов. Число аккаунтов не является числом уже приглашённых людей.

Регистрация не выдаёт модераторские права. Оператор подтверждает UUID нужных тестовых аккаунтов через их собственный GET /api/me, затем задаёт COMMUNITY_MODERATOR_IDS при перезапуске по MODERATION.md. Нельзя использовать номер 1, никнейм или произвольный UUID. Сеансы и CSRF-токены из ответа не копировать в отчёт. До назначения двух независимых модераторов сценарий апелляции помечается BLOCKED.

## Задания участникам

Ведущий сначала даёт цель, а не последовательность кнопок. Если потребовалась подсказка, записывает её.

| № | Задание | Ожидаемый результат |
|---|---|---|
| 1 | Создать аккаунт, поменять имя, выйти и войти | Сохранены имя и доступ; пароль не показан |
| 2 | Создать клуб по заявкам; другому игроку вступить | До принятия посты и чат закрыты; после принятия доступны |
| 3 | Опубликовать пост, ответить комментарием и в чате | Авторство верно, данные остаются после обновления страницы |
| 4 | Открыть закрытый пост и чат посторонним | Приватный текст не показан |
| 5 | Заблокировать участника клуба во время чата | На следующем опросе история очищается, новые отправки запрещены |
| 6 | Написать незнакомому игроку, затем принять запрос | До принятия нет обычной переписки; после принятия можно отвечать |
| 7 | Пожаловаться на первое сообщение, не принимая запрос | Запрос остаётся ожидающим; модератор получает только предусмотренный контекст |
| 8 | Рассмотреть жалобу, прочитать решение и подать апелляцию | Второй независимый модератор пересматривает; оба решения сохранены |
| 9 | Создать группу на двоих, подать и принять заявку | Ожидающий не читает чат; принятый получает доступ; третьего места нет |
| 10 | Закрыть группу, прочитать историю, выйти | После закрытия нельзя отправить; после выхода нет доступа к чату |
| 11 | Потерять связь при отправке и повторить сообщение | Понятный статус ошибки; повтор не создаёт дубль |
| 12 | Перезапустить сервер и выполнить тренировку восстановления | Записи сохранены; восстановление проводится только в отдельном каталоге по BACKUP.md |

Дополнительно вручную: клавиатура и видимый фокус, масштаб 200%, длинные названия, ошибки форм, возврат между разделами. Телефон и экранная клавиатура остаются непроверенными до доступного подходящего стенда.

## Приёмка и остановка

Каждое задание получает PASS, FAIL или BLOCKED с доказательством. Пропущенное задание не считается успешным. Записать реальные результаты в PILOT_REPORT.md, не превращать список автотестов в отзыв участников.

Немедленно остановить сессию при чужом доступе, утечке приватных данных, неверных правах или потере сохранённых записей. Прекратить ввод, остановить сервер, сохранить закрытую копию для разбора; не прикладывать её к GitHub. Для ошибки интерфейса записать шаги и продолжать только если она не мешает надёжно оценить остальные задания.

Для завершённой локальной сессии: основной путь 1–4 и 6,9–10 выполнен; остальные статусы явно записаны; нет открытых критических дефектов; замечания ранжированы, назначены следующие действия. Это не разрешение публичного запуска.
