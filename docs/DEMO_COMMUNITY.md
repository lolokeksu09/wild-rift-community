# Люди, ссылки и демонстрационное наполнение · 0.26

По поручению владельца добавлено временное наполнение: 24 явно обозначенных бота, 6 открытых клубов, 24 публикации (включая 3 руководства), 72 комментария и 18 примеров сообщений в клубных чатах. Аватары и обложки созданы геометрической графикой внутри проекта. Существующие аккаунты, клубы и записи сохраняются.

Это статичные демонстрационные аккаунты: они не отвечают, не играют, не создают группы или события, не пишут личные сообщения и не получают сеансы входа. Ранги, Riot ID, статистика игры и присутствие онлайн не выдумываются. Карточки, профили, публикации и комментарии показывают отметку «Бот»; клубы — «Демо», чатные примеры содержат явное пояснение. Счётчики клуба отдельно показывают число ботов. Боты не являются модераторами платформы. Управление их клубами требует отдельного операторского решения.

## Навигация и доступ

Прямые ссылки `/clubs/<id>`, `/posts/<id>`, `/players/<id>` работают после обновления страницы и с кнопками браузера назад/вперёд. Сервер отдаёт оболочку только для перечисленных маршрутов, затем API проверяет доступ к содержимому. Неизвестные пути возвращают 404. Несохранённый редактор предупреждает перед уходом, редактор черновика сохраняется перед переходом.

Раздел `/players` («Люди») доступен гостям: поиск имени/логина, фильтр роли, страницы по 20 профилей. `GET /api/community-members` показывает только явно опубликованные профили и учитывает двусторонние блокировки текущего пользователя. Поля пароля, сеансов и приватный Riot ID не выдаются. Поиск компании `/api/players` сохраняет прежнюю авторизацию.

В открытом клубе гость видит кнопку входа для вступления. Безопасный параметр `return=/clubs/<id>` переживает обновление формы. После входа/регистрации открывается клуб; вступление требует отдельного действия. Общие правила доступны по `/rules`, фактическая жалоба — через существующий интерфейс публикации/сообщения. Контакт поддержки и штат сотрудников не выдумываются.

## Операторское наполнение

`node server/demo-seed-cli.mjs <путь-к-SQLite>` запускается только оператором. Подготовка изображений предшествует единой транзакции. Детерминированные идентификаторы и clientId предотвращают повторные вставки; столкновение с чужим аккаунтом/владельцем клуба отменяет транзакцию. Маркер `game_profile.demoBot=community-v1` создаётся только операторским кодом: API профиля не принимает его от клиента, API не выдаёт внутренний маркер, вход ботов отвергается.

Установщик выполняет наполнение только при `SEED_DEMO_COMMUNITY=1` и отсутствии `/opt/wild-rift-community/demo-seeded-v1`. Workflow 0.26 задаёт этот флаг. После успешной публикации записывается маркер, поэтому следующие развёртывания не восстанавливают удалённые демонстрационные записи автоматически. Схема остаётся 19, новые зависимости не добавлены.

Перед наполнением приложение останавливается под страницей обслуживания, сохраняется холодная копия всего `data`. Ошибка до открытия трафика восстанавливает старую конфигурацию и базу; после открытия база автоматически не заменяется, чтобы не потерять новые записи людей. См. DEPLOYMENT.md и BACKUP.md. Внешнее резервирование остаётся неподключённым.

Автоматического удаления ботов нет. Перед удалением или передачей клубов нужно отдельно учесть вступивших людей, их публикации, ответы и вложения; откат всей старой базы после появления настоящего контента недопустим.

## Проверки

Серверные тесты проверяют повтор наполнения, сохранение настоящего аккаунта, транзакционный отказ при столкновении, невозможность входа бота/присвоения маркера, приватность каталога, блокировки и недоступность закрытых публикаций по прямым ссылкам. Браузерный сценарий `tests/browser-discovery.mjs` проверяет 360/390/768/1440 px: отметки, пагинацию, прямые ссылки/обновление/историю, регистрацию с возвратом в клуб, явное вступление и разделение людей/ботов в счётчиках. Docker preflight повторяет наполнение на изолированной копии базы и проверяет отсутствие дублей.
