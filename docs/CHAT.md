# Чат клуба · версия 0.4

## Готово

- Одна общая комната клуба в серверном клиенте.
- Доступ только действующим участникам, включая открытые клубы. Гости, ожидающие заявки, вышедшие и заблокированные читать не могут.
- Сообщения до 2000 символов с автором и временем.
- Постоянное хранение в SQLite и восстановление после перезапуска.
- Последние 50 сообщений при входе; кнопка ранней истории.
- HTTP-опрос раз в 2 секунды; подгрузка всех пропущенных страниц после восстановления связи.
- Повтор отправки с прежним clientId не дублирует запись. Другой текст с тем же ID получает 409.
- Отдельная локальная очередь неподтверждённых сообщений. Перед повтором сервер может уже подтвердить запись через опрос.
- Уход со страницы останавливает обновления и отменяет активные запросы; поздний ответ прежней комнаты не меняет новую страницу.

Это HTTP polling, а не push/WebSocket. При отзыве доступа сервер запрещает следующий запрос немедленно; интерфейс узнаёт об изменении при следующем успешном обращении. При отсутствии сети невозможно мгновенно узнать о бане. Загруженные ранее сообщения могут оставаться видимыми до восстановления связи.

## Отправка и повтор

POST `/api/clubs/:id/messages`

Тело: `{ "clientId": "уникальный ASCII ID длиной 16–80", "body": "текст" }`. Формат ID: латиница, цифры, `_` и `-`; интерфейс создаёт UUID. Это описание полей, не готовый пример ID.

201: новая запись; 200 с `replayed:true`: та же запись уже существует. Уникальность действует в пределах клуба и пользователя. Автор определяется из сеанса, не из тела запроса. Права проверяются перед поиском повторной записи: после бана даже повтор ранее принятого сообщения запрещён.

Неподтверждённые попытки сохраняются в sessionStorage текущей вкладки, отдельно для аккаунта/клуба. При недоступном хранилище показывается предупреждение и очередь работает в памяти. При закрытии вкладки гарантия восстановления очереди отсутствует. Сетевой запрос чата отменяется через 10 секунд без ответа. Явный выход из аккаунта очищает его локальную очередь. Кнопка «Убрать из очереди» не удаляет сообщение, уже принятое сервером; перед действием показывается предупреждение.

## Получение

GET `/api/clubs/:id/messages` — последние 50, в хронологическом порядке.

`?before=ID` — до 50 сообщений старше ID; `?after=ID` — до 50 новее ID. Вместе параметры запрещены. Ответ: `viewerId`, `messages`, `hasMore`, `next`. Для after при наличии следующей страницы next — последний ID; для before — первый. Начальные/старые выборки возвращаются по возрастанию ID для отображения.

Курсор новых сообщений продвигается только при чтении истории. Подтверждение собственного сообщения его не двигает: иначе можно пропустить чужое сообщение, отправленное между двумя запросами.

## Миграция SQLite 1→2

Перед обновлением остановить сервер и скопировать весь каталог базы `data` (или каталог COMMUNITY_DB). Первый запуск добавит `messages`, индекс и user_version=2. Старые аккаунты, клубы, посты, комментарии и сеансы не изменяются. Создание таблицы и обновление версии выполняются в транзакции.

Для возврата к версии 0.3 остановить сервер и восстановить ранее сделанную копию базы. Это потеряет новые данные, созданные после копирования, поэтому откат требует отдельного решения владельца. Старый код отказывается открывать новую схему. Не менять user_version вручную.

В этой разработке миграция проверялась только на временной тестовой базе; пользовательская рабочая база не запускалась и не обновлялась.
