# Личные сообщения · 0.5

С 0.30 создание новых исходящих знакомств ограничено отдельным сохраняемым бюджетом и паузой. Подробности, API 429 и настройки — [CONTACT_LIMITS.md](CONTACT_LIMITS.md). Принятые беседы и идемпотентные повторы не расходуют бюджет.

Расширение 0.28: `GET /api/direct?after=CURSOR` возвращает до 50 бесед и `next`; клиент догружает их кнопкой. Общие `unread`/`requests` учитывают все доступные беседы, включая следующие страницы. `GET /api/direct/summary` выдаёт только `{viewerId,unread,requests}`, а общий `GET /api/notifications/summary` объединяет пять счётчиков. Фоновое обновление счётчиков: 5–30 секунд при видимой вкладке, пауза скрытой, backoff до 60 секунд при ошибках. Чаты сохраняют свой прежний интервал. [Детали 0.28](AUDIT_FIXES_2026-10-04.md).

Вкладка «Сообщения»: беседы, входящие, отправленные и отклонённые запросы; создание запроса по точному логину; настройка получения новых запросов; список личных блокировок.

Первый запрос содержит ровно одно сообщение. Только получатель может принять или отклонить его. До принятия дополнительных сообщений нет. Отклонение окончательно для этой пары аккаунтов: повторный запрос не создаётся. Встречный запрос не считается согласием. Одна пара имеет одну беседу.

Принятые беседы используют серверное хранение SQLite, страницы истории по 50 сообщений, опрос раз в 2 секунды и ту же очередь повторов, что чат клуба. Идентификатор отправки предотвращает дубли. Первоначальный запрос сохраняет идентификатор при повторе в открытой форме; после перезагрузки надо обновить список, чтобы проверить доставку. Он не сохраняется как локальный черновик.

Блокировка здесь относится к личной переписке: закрывает чтение и отправку с обеих сторон, скрывает беседу из списка. Снятие всех блокировок возвращает доступ к принятой беседе. Данные не удаляются. Уже полученные копии отозвать невозможно. С версии 0.10 сообщения заблокированных тобой авторов скрываются и в общих чатах; см. CHAT.md. Открытая беседа очищается при следующем запросе с отказом; список запросов обновляется кнопкой. Изменение настройки запросов не отменяет существующие запросы и беседы.

## API

Все маршруты требуют сеанс. Изменения дополнительно требуют Origin, CSRF и X-Community-Request.

- GET /api/direct — только собственные беседы, первые сообщения запросов.
- POST /api/direct — {handle, clientId, body}; создание запроса или повтор той же отправки.
- POST /api/direct/:id/decision — {decision: accept|reject}; только получатель.
- GET /api/direct/:id/messages — принятая беседа; before либо after.
- POST /api/direct/:id/messages — {clientId, body}; принятая беседа.
- PATCH /api/me/privacy — {dmRequests: boolean}.
- GET /api/blocks — собственные блокировки.
- POST /api/blocks и DELETE /api/blocks — {userId}; установить/снять собственную блокировку.

Чужая беседа возвращает 404, блокировка/непринятый запрос — 403. Разрешения проверяются до чтения и повторной отправки. Личные сообщения не имеют сквозного шифрования; оператор базы может их прочитать.

## Непрочитанное · 0.6

GET /api/direct возвращает unread для каждой принятой беседы, общий unread и requests — количество ожидающих входящих запросов. Считаются только чужие сообщения после собственной отметки прочтения. Заблокированные беседы исключены. Открытие списка само по себе ничего не отмечает.

POST /api/direct/:id/read принимает {lastId}: существующий ID сообщения именно этой принятой беседы. Отметка принадлежит авторизованному пользователю и двигается только вперёд. Подмена пользователя не поддерживается. В интерфейсе кнопка «Отметить загруженное прочитанным» использует максимальный загруженный ID; пришедшее позже сообщение остаётся непрочитанным. Кнопка отмечает и более ранние сообщения этой беседы, даже если они не показаны на последней странице. Собеседнику отметка прочтения не раскрывается.

Кнопка навигации показывает общее непрочитанное и число запросов, обновляясь каждые 5 секунд. Список бесед по-прежнему обновляется вручную. Это уведомления внутри работающего приложения; push, звук, системные уведомления и счётчики клубных чатов не реализованы.

Миграция 3→4 транзакционно добавляет direct_reads. Старые сообщения не изменяются; первоначально все входящие сообщения считаются непрочитанными. Перед обновлением остановить сервер и скопировать каталог data. Для отката восстановить копию и старую версию приложения; вручную версию схемы не понижать.

Проверки 0.6: npm test — 32 passed. server-ui, chat-ui, direct-ui — PASS (DOM, без визуальной проверки). Добавлены проверки счётчиков запросов, независимости отметок пользователей, запрета чужих/несуществующих ID, сохранения после перезапуска, монотонности и блокировки. Интерфейсный тест подтверждает действие кнопки прочтения.


## Оформление списка бесед — этап 17

`GET /api/direct` дополнительно возвращает в каждой записи `peer_avatar_id` (null для неопубликованного профиля), `peer_is_bot`, `last_body`, `last_created_at`, `last_sender_id`. Последние три поля заполняются только для принятой беседы; для ожидающего или отклонённого запроса — null, доступно прежнее `first_body`. Полный игровой профиль не возвращается. Список остаётся доступным только участнику и исключает блокировки в любую сторону. Курсор, порядок списка, счётчики и схема SQLite 22 не менялись. Старые клиенты могут игнорировать дополнительные поля.

Веб-список показывает доступный аватар, настоящее последнее сообщение (до 140 символов), «Ты:» для собственного, время/дату и число непрочитанных. При отсутствии аватара или ошибке загрузки остаётся инициал. До получения новых полей от сервера используется первое сообщение; выдуманных дат нет. Метки ботов сохранены. Возврат из беседы обновляет список; открытие не отмечает историю прочитанной. Кнопки принятия, отказа, жалобы, блокировок, приватности и догрузки сохранены. Ссылка «Клубы и их чаты» открывает каталог: объединённый список личных и клубных чатов ещё не реализован.
