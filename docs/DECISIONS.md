# Решения и вопросы

## Подтверждено пользователем

- Отдельный проект по Wild Rift, не продолжение RiftCore.
- Большое сообщество с общением между людьми, по духу Amino.
- Нужны ТЗ, оформление GitHub и понятный порядок старта.

## Предложено в этом пакете

- Первый клиент: адаптивный web с возможностью установки.
- Первый язык интерфейса: русский.
- Репозиторий на старте приватный.
- Документация и интерфейс не используют невыбранное брендовое название.
- Первый релиз без голосового сервера, видеохостинга и интеграции с игровыми данными.
- Хронологическая лента раньше рекомендательного алгоритма.

Эти решения можно пересмотреть до реализации соответствующего модуля.

## ADR-001 · 29.09.2026 · локальный серверный этап

Для проверяемого локального сценария выбраны Node.js 24.19+ в ветке 24.x, встроенный HTTP-сервер и SQLite через node:sqlite. Причина: доступная среда, нет расходов и внешних runtime-зависимостей, можно протестировать общение двух аккаунтов и права на настоящей базе.

Это обратимое инженерное решение для разработки, не согласование production-стека. SQLite синхронный; горизонтальное масштабирование и публичные нагрузки не оценивались. Локальная схема логин/пароль не заменяет будущий выбор подтверждения email, восстановления и провайдера входа. Хостинг, бюджет и публичный запуск остаются открытыми.

Пароли хешируются scrypt со случайной солью; сеансы хранятся на сервере. HTTP разрешён только на loopback. Запуск с NODE_ENV=production запрещён. При выборе размещения нужно пересмотреть TLS, cookies, rate limiting, наблюдаемость и хранение.

Первичные технические источники: https://nodejs.org/docs/latest-v24.x/api/crypto.html и https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html. Важные API проверены также на установленном Node 24.19.0.

## ADR-002 · 29.09.2026 · чат клуба

Первый серверный чат использует HTTP-опрос раз в 2 секунды и курсор по неизменяемому ID сообщения. На этом этапе не добавляем WebSocket-сервис и новые зависимости. При возврате после разрыва клиент получает пропущенные страницы; для более старой истории есть отдельный курсор.

Клиент генерирует идентификатор каждой попытки отправки, сервер обеспечивает уникальность (клуб, автор, clientId) и отвергает изменение текста с уже использованным ID. Неподтверждённые попытки находятся в sessionStorage под ключом пользователя и клуба; их можно повторить, сервер не создаёт дубль. При отзыве доступа клиент очищает показанную историю и локальную очередь на следующем запросе. Это не удаляет уже прочитанное из памяти человека или сделанные им копии.

Миграция 1→2 только добавляет таблицу и индекс сообщений. Production realtime, личные сообщения, уведомления, поиск и модерация переписки остаются отдельными задачами.

## ADR-003 · 29.09.2026 · личные запросы

Личная беседа уникальна для пары аккаунтов и открывается только после явного согласия получателя. До согласия хранится одно сообщение. Отклонение окончательно в текущем этапе; повторное открытие потребует отдельного пользовательского сценария. Блокировка закрывает личную историю для обоих участников до снятия всех блокировок. Запрет новых запросов не закрывает прежние беседы. HTTP-опрос и существующий контроллер истории используются повторно без новых runtime-зависимостей. Миграция 2→3 аддитивная; подробности и ограничения — DIRECT_MESSAGES.md.

## ADR-004 · 29.09.2026 · отметки прочтения

На локальном этапе используется явная отметка прочтения до максимального загруженного ID, без определения видимости сообщения на экране. Сервер хранит монотонный курсор отдельно для каждого участника. Счётчики вычисляются по сообщениям, поэтому повтор доставки не создаёт отдельное уведомление. Обновление навигации — HTTP раз в 5 секунд. Push и клубные счётчики остаются отдельными задачами. Миграция 3→4 добавляет только direct_reads.

## ADR-005 · 29.09.2026 · рассмотрение жалоб

Модератор получает снимок выбранного сообщения и пояснение, без произвольного доступа к беседе. Роль локально задаётся оператором по ID аккаунта в COMMUNITY_MODERATOR_IDS, не через профиль. Собственные жалобы и жалобы на себя требуют другого модератора. Решение окончательно в текущем этапе, сохраняется с аудитом; санкции и апелляции ещё не реализованы. Миграция 4→5 добавляет таблицы без удаления данных. См. MODERATION.md.

## ADR-006 · 29.09.2026 · уведомления о решениях

Собственные решения по жалобам имеют явную отметку прочтения. Счётчик использует состояние жалобы, без отдельного события на каждый повтор решения. Получатель — только заявитель; модератор не управляет его отметкой. Опрос интерфейса — 5 секунд. Схема 5→6 добавляет decision_seen; общая система событий и push остаются вне этого этапа.

## ADR-007 · 29.09.2026 · независимый пересмотр

Для локального этапа: одна неизменяемая апелляция заявителя на завершённую жалобу. Второй модератор не должен совпадать с первым, заявителем или автором спорного сообщения. Первое решение не перезаписывается; результат пересмотра хранится отдельно и считается итоговым по жалобе. Автоматических санкций нет. Собственные отметки прочтения двух результатов независимы. Для production ещё предстоит определить сроки, обжалование санкций и правила назначения независимого модератора.

## ADR-008 · 29.09.2026 · фильтрация общего чата

Личная блокировка скрывает сообщения автора для заблокировавшего пользователя, не изменяя членства клуба. Фильтрация выполняется до серверной пагинации. Версия блокировок хранится в users.block_version и увеличивается в транзакции при изменении; клиент отвергает старые ответы и перезагружает историю после смены версии. Позиция прокрутки при этом не сохраняется. Посты/комментарии этим этапом не затронуты.

## ADR-009 · 29.09.2026 · поиск напарников

Локальный первый этап: группы на 2–5 игроков, автор занимает место, один фильтр нужной роли, самозаявленные регион/язык/ранг. Вместимость проверяется в синхронной транзакции. Ожидающая заявка не открывает состав и чат; принятые участники получают общий приватный чат. Закрытие/истечение сохраняет чтение истории для оставшихся участников, запрещая набор и отправку. Отклонённая заявка не переоткрывается. Возможность редактирования, уведомления и модерация групп требуют отдельного этапа. Данные Riot не используются; лимиты приложения не гарантируют совместимость с игровой очередью.

## ADR-010 · 29.09.2026 · события поиска напарников

Событие и изменение группы сохраняются одной транзакцией; получатель задан сервером, повтор неизменившегося действия не создаёт дубль. Уведомления не содержат текста чата или состава, только тип события и номер группы. После перехода проверяется актуальный доступ. Прочтение явное, индивидуальное. Push и автоматические напоминания не входят в локальный этап.


## ADR-011 · 03.10.2026 · профили и медиа

Владелец поручил следовать расширенному ROADMAP. 0.14 добавляет ручные игровые поля, опциональный публичный профиль и отдельную видимость Riot ID. Без Riot API и игровых изображений. Sharp 0.35.5 — одна обоснованная runtime-зависимость для безопасного декодирования, ориентации и перекодирования без исходных метаданных. Файлы хранятся BLOB в SQLite в рамках квот раннего VDS; общая холодная копия сохраняет их вместе с контентом. Один файл привязан к одному месту, доступ проверяется на каждом GET, включая отзыв членства/бан. Обложки клубов публичны. Миграция 10→11 под обслуживанием: проверка копии, переход, healthcheck, публикация. Возврат холодной базы допустим только до открытия трафика; после публикации новые записи сохраняются до анализа аварии.


## ADR-012 · 03.10.2026 · поиск игроков

0.15 следует согласованному ROADMAP. В поиск попадают только опубликованные профили; выдача доступна вошедшему пользователю, исключает его собственный профиль и блокировки с обеих сторон. Фильтры применяются в SQLite до LIMIT; нормализация NFKC/нижний регистр выполняется зарегистрированной JS-функцией wr_fold, чтобы кириллица работала корректно. Пагинация по неизменяемому логину ASC; это не порядок присутствия или игровой активности. Новое поле microphone сохраняется в существующем JSON профиля, схема остаётся 11. Ранг/регион/язык — ручные значения, точное совпадение без учёта регистра, без обещания совместимости игровой очереди. Карточка «Написать» только открывает существующий редактор личного запроса с логином; сообщения автоматически не отправляются.

## ADR-013 · 03.10.2026 · обсуждения

0.16 следует ROADMAP. Один игрок выбирает одну реакцию на публикацию; PUT задаёт итоговый выбор, DELETE снимает, без toggle на сервере. Ответы только на исходный комментарий: фиксированная глубина и компактная цитата, хронологический список с догрузкой старых записей. Личный список сохранённого не даёт новых прав. @логин уведомляет существующего участника клуба; максимум 10 уникальных упоминаний, без уведомления самого себя или заблокированного игрока. События не хранят снимок текста. Уведомление и комментарий/пост сохраняются атомарно; уникальность события предотвращает дубль при ответе и упоминании того же игрока. Новый клиент сохраняет clientId для повтора после потери ответа; старые клиенты без clientId поддержаны без гарантии идемпотентности. Схема 11→12 аддитивная. Блокировки с обеих сторон теперь фильтруют также посты/комментарии и их вложения. Внешние push, изменение/удаление комментариев и глубокие ветки — отдельные этапы.

## ADR-014 · 03.10.2026 · управление клубами

0.17 следует ROADMAP. Роль модератора принадлежит паре (клуб, участник), требует активного членства и не связана с модерацией платформы. Владелец управляет правилами/метками/акцентом, обложкой, ролями, приглашениями и передачей; модератор рассматривает заявки, управляет обычными участниками, закрепляет и удаляет посты. Владелец/модератор защищены от санкций до снятия роли владельцем. Передача — предложение на 24 часа и явное согласие получателя; смена владельца, снятие ролей передающей пары и отзыв всех старых приглашений атомарны. Приглашение помогает найти клуб, но сохраняет его обычный порядок вступления и запрет бана. Token выводится в fragment URL, API получает его в теле; SQLite хранит только hash. Token создаётся HMAC-SHA256 из секретного CSRF текущего сеанса и clientId/клуба, чтобы повтор запроса в том же сеансе вернул ту же ссылку без хранения исходника. После смены сеанса повтор старого clientId требует новой формы. Схема 12→13 аддитивная; журнал управления доступен только текущему владельцу/модераторам.

## ADR-015 · 03.10.2026 · игровые вечера

0.18: самостоятельные события, без привязки к клубу и переноса членства. Организатор занимает одно из 2–5 уникальных мест по роли. Остальные записываются сразу без заявок; атомарный UPDATE свободного места и UNIQUE(event,user) запрещают переполнение. Исключение окончательно для этого события. Дата хранится UTC-epoch вместе с выбранным IANA-поясом; клиент отказывается от неоднозначного или отсутствующего местного времени при переводе часов. Набор прекращается в момент начала, чат пишет до окончания; отмена оставляет чтение текущему составу. Напоминания создаются при обращении текущего получателя в последние 30 минут до начала, не рассылаются вне приложения. Блокировки с организатором закрывают событие/чат/уведомления; состав других участников не выводится до записи. Схема 13→14 аддитивная.

## ADR-016 · 03.10.2026 · личная главная

0.19 добавляет read-only GET /api/home для текущего сеанса. Игровые поля собственного закрытого профиля могут использоваться для личного подбора; endpoint не принимает чужой userId. Клубы требуют актуального принятого членства; события — своего места, отсутствия отмены и окончания. Подбор групп использует точное нормализованное совпадение заполненных региона/языка/ранга, одну из ролей или any, отказ от обязательного голоса при microphone=no; отбрасывает полные/закрытые/истёкшие группы, свои группы, свои активные/отклонённые заявки и блокировки. Критерии видны игроку, не обозначаются проверенной совместимостью очереди. Прямые ссылки передают только ID существующим контроллерам, которые снова проверяют права на сервере. Гостевая главная и хронологическая лента сохранены. Схема остаётся 14, новых зависимостей и фоновых рассылок нет.

## ADR-017 · 03.10.2026 · серверные черновики

0.20: один приватный черновик на клуб/автора с версией. PUT допускает неполный текст, проверяет текущее членство и владение вложением; одинаковый повтор с прежней версией возвращает прежнее сохранение. Автор не может присвоить изображение черновика другому месту. Публикация требует версии/clientId, переносит вложение и отправляет обычные упоминания одной транзакцией; повтор после потери ответа возвращает прежний postId, новый черновик при старом clientId защищён конфликтом. DELETE и удаление членства каскадно очищают неиспользуемое вложение; бан закрывает доступ, не публикует и не стирает текст. UI хранит несохранённые изменения только в памяти текущей вкладки, не в localStorage; перед закрытием предупреждает, сохраняет при навигации, отказывает в перезаписи при конфликте. Схема 14→15 аддитивная; холодная копия перед миграцией.

## ADR-018 · 03.10.2026 · редактирование и поиск публикаций

0.21: PATCH своего поста требует текущего членства, edit_version и clientId. Повтор последней подтверждённой попытки возвращает ту же версию, иной текст с тем же ID или устаревшая версия даёт 409. Изображение не меняется, комментарии/реакции/сохранения остаются, порядок по created_at/id не меняется. Изменение не рассылает новые упоминания; уведомления читают актуальный заголовок без снимка. Поиск literal substring по NFKC/нижнему регистру заголовка и тела, права и блокировки до LIMIT; гости видят только открытые клубы, бан закрывает и открытый клуб. Схема 15→16 аддитивная.

## ADR-019 · 03.10.2026 · опросы клуба

0.22: опрос — обычная публикация со связанными вариантами, сроком UTC и голосами. Создание требует членства и clientId; повтор неизменённого payload возвращает тот же пост. Вопрос/варианты/срок после публикации не редактируются, чтобы выбор не изменял смысл. PUT задаёт один неизменяемый optionId; одинаковый повтор возвращает результат даже после закрытия, но только при актуальных правах. Новый голос после ends_at отвергается в транзакции. Результаты доступны читателям поста без списка голосовавших, показывают только текущих принятых участников и исключают двусторонние блокировки зрителя. Выход удаляет голос каскадно; после повторного вступления можно голосовать снова в открытом опросе. Бан скрывает голос из подсчёта и закрывает доступ. Автоматических рассылок и внешних сервисов нет, обычные упоминания работают при создании. Схема 16→17 аддитивная.
