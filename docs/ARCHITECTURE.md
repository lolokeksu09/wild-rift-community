# Архитектура проекта

Актуализировано 05.10.2026. Android — основной будущий клиент; его [архитектура](android/ARCHITECTURE.md) описана отдельно.

```text
Android UI → ViewModel → Repository → HTTPS API
                                           ↓
Web UI ───────────────────────────────→ серверные правила → SQLite
```

Сегодня сервер — Node.js 24, модули JavaScript .mjs, встроенный SQLite, Sharp для изображений. Точка HTTP-обработки — server/app.mjs; тематические модули делят клубы, каталог, обсуждения, профили, общение и модерацию. server/public/ содержит браузерный клиент. Docker/Caddy обеспечивают опубликованный HTTPS.

Аккаунты и права общие для клиентов. SQLite содержит и изображения в media BLOB. Не переносить правила доступа, роли, блокировки, лимиты контактов и модерацию в приложение. Ответ API обязан проверять их независимо от экрана.

Авторизация сейчас cookie + CSRF + точный Origin + маркер запроса. Нативная совместимость ещё требует проверки; [контракт](android/API_CONTRACT.md). Не отключать браузерную защиту и не вводить второй набор бизнес-правил.

Один сервер и один Android app-модуль достаточны для начала. SQLite не заменять без измеренной потребности и отдельного плана миграции. Каталоги server/public и tests не перемещать косметически: на них завязаны Docker и проверки.

Риски и порядок устранения — [аудит](android/REPOSITORY_AUDIT.md). Раннее описание сохранено в [истории](history/2026-10-05-ARCHITECTURE.md).
