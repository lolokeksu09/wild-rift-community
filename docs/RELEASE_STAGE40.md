# Этап 40 — список ожидания игровых событий

Полный выпуск включает этапы 1–39 и утверждённый дизайн.

- На занятую или временно зарезервированную роль можно встать в очередь. Порядок — по времени записи через возрастающий ID; один игрок ожидает одну роль в событии, максимум 50 активных записей на роль.
- Когда место освобождается, оно предлагается первому допустимому игроку на 10 минут, до начала события. Остальные не могут занять зарезервированное место обычной записью.
- Игрок подтверждает участие, отказывается или выходит. Без подтверждения он не в составе, не читает чат, не появляется в «Моих играх» и календаре.
- Отказ/истечение срока передают предложение следующему. Исключённые и заблокированные с организатором игроки пропускаются. Начало и отмена закрывают очередь.
- Собственная позиция, число ожидающих на роль, время окончания предложения и уведомления с точной ссылкой. Имена очереди другим игрокам не раскрываются; видны только числа и факт резерва.
- Повтор записи после потери ответа не дублирует очередь; старое подтверждение после выхода не занимает место заново. Для повторного вступления после отказа/истечения/выхода нужен новый идентификатор и новый выбор игрока.
- Активная очередь показывается в фильтре «Мои» игровых событий. Открытая страница очереди обновляется каждые 15 секунд, без фоновой перерисовки чата участника.
- Исправлена первая загрузка прямой ссылки `/events?id=...`: после проверки сеанса нужный ID сохраняется.

Очередь обрабатывается при запросах сайта, фонового процесса и внешней доставки нет. Срок предложения проверяется сервером даже при устаревшей странице; после паузы следующий игрок получает новое предложение при очередном запросе. Настройка категории событий из этапа 39 действует на счётчик и общий центр. Уведомление не принимает место вместо игрока.

SQLite **32** добавляет очередь и расширяет допустимые типы уведомлений событий. Существующие события, составы, сообщения, прочитанность, ID уведомлений и последовательность ID сохраняются. Установщик проверяет холодную копию и сохраняет резервную копию. Приложение схемы 31 не открывает базу 32; после установки не откатывай базу автоматически, теряя новые данные. Дизайн и `.github/workflows/vds-deploy.yml` сохранены; боевой deploy не выполнен.

Проверки: реальные HTTP/SQLite для FIFO, приватности, конкуренции, повтора, отказа, истечения, исключения, блокировок, отмены, начала, миграции и ID; DOM для потери ответа, кнопок, повторной записи, отзыва чата и позиции. Итог verify и CI — в [PROJECT_STATE.md](../PROJECT_STATE.md).

Скачай ZIP в `/storage/emulated/0/Download`, затем:

```bash
bash "$HOME/wr-deploy/wr-deploy-latest.sh"
```

После установки: «Игровые вечера» → событие → у занятой роли «Встать в очередь». Дождись предложения и нажми «Подтвердить участие».
