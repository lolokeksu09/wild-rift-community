# Сообщество игроков Wild Rift

Статус: работающая ранняя версия сообщества. Локально подготовлен выпуск 0.28 с исправлениями аудита: жалобы на публичные материалы, защита профиля, пагинация и более экономные счётчики. Публикация подтверждается результатом GitHub Actions; наличие изменений в репозитории не означает обновление живого сайта.
Название продукта пока не выбрано. Репозиторий: `lolokeksu09/wild-rift-community`, приватный, основная ветка `main`. Это отдельный проект, не RiftCore.

Социальная платформа по духу Amino: профили, публикации, клубы, чаты и поиск компании для Wild Rift. Главный сценарий: найти свой клуб, познакомиться и сыграть вместе.

Оформление, первое знакомство и границы гостевого доступа — [COMMUNITY_DESIGN.md](docs/COMMUNITY_DESIGN.md).

Каталог с тематическими фильтрами, чтение публикаций, копирование ссылок и первые шаги 0.27 — [COMMUNITY_REFINEMENT.md](docs/COMMUNITY_REFINEMENT.md).

Исправления аудита 0.28, миграция 19→20 и процедура передачи демо-клубов — [AUDIT_FIXES_2026-10-04.md](docs/AUDIT_FIXES_2026-10-04.md).

## С чего начать

1. Прочитать [ТЗ](docs/SPEC.md) и [план](docs/ROADMAP.md).
2. Открыть `docs/prototype.html` в браузере: это автономный прототип с демонстрационными данными. Посты, комментарии, членство, заявки и сообщения сохраняются только в этом браузере.
3. Зафиксировать решения из [DECISIONS.md](docs/DECISIONS.md).
4. Выбрать следующую задачу в [GitHub Issues](https://github.com/lolokeksu09/wild-rift-community/issues).
5. Реализовать один сквозной сценарий по плану, затем провести закрытый пилот.

## Что уже существует

Работающий серверный клиент с аккаунтами, SQLite, клубами, постами/комментариями, общими и личными чатами, поиском группы, уведомлениями, блокировками и модерацией. Актуальный функционал и следующие этапы — в ROADMAP. Автономный прототип v0.2 остаётся историческим эскизом. Сервис ранний, готовность к массовому запуску не подтверждена. Репозиторий создан владельцем: https://github.com/lolokeksu09/wild-rift-community.

## Лицензия и материалы

Лицензия исходного кода ещё не выбрана. Игровые изображения и логотипы в пакет не включены. До использования внешних ресурсов необходимо зафиксировать источник и условия использования. Проект не заявляет официальную связь с Riot Games.

## Проверка прототипа v0.2

См. [отчёт о проверках](docs/PROTOTYPE_QA.md). Для DOM-тестов:

```bash
npm ci --prefix tests
npm test --prefix tests
```

Нужна версия Node, указанная в tests/package.json. Эти зависимости нужны только для тестирования; HTML открывается самостоятельно и не загружает внешние ресурсы. DOM-тесты не заменяют визуальную проверку в браузере.

## Локальная серверная версия 0.3

Нужен Node.js 24.19.x или более новая версия 24.x. В папке репозитория:

```bash
npm start
```

Открыть адрес из вывода (по умолчанию `http://127.0.0.1:3000`). Для текущей версии перед запуском выполнить `npm ci`; ранняя 0.3 не имела runtime-зависимостей. Сервер слушает только локальный интерфейс. Это отдельный работающий клиент; `docs/prototype.html` остаётся автономным дизайн-прототипом.

```bash
npm test
```

См. [SERVER.md](docs/SERVER.md) — запуск, ограничения и API; [отчёт](docs/SERVER_QA.md) — выполненные проверки.

## Чат клуба · 0.4

В серверном клиенте появилась общая комната каждого клуба. Сообщения хранятся в SQLite, новые загружаются опросом раз в две секунды. Даже в открытом клубе чат доступен только участникам. Повтор отправки использует тот же идентификатор и не создаёт дубль.

[Поведение, миграция и проверки](docs/CHAT.md). Перед первым запуском 0.4 поверх 0.3 остановить сервер и скопировать каталог базы: схема обновится с 1 до 2. Сервер остаётся локальным. Личные чаты добавлены следующим этапом 0.5.

```bash
npm run test:chat-ui --prefix tests
```

## Личные сообщения · 0.5

Запрос первого сообщения, принятие/отклонение, личная переписка, настройка запросов и блокировка доступны во вкладке «Сообщения». [Поведение, миграция 2→3 и проверки](docs/DIRECT_MESSAGES.md).

```bash

```

## Непрочитанное · 0.6

В личных беседах доступны счётчики входящих сообщений и кнопка отметки прочтения. Навигация показывает непрочитанное и входящие запросы, обновляясь раз в 5 секунд. Это уведомления внутри приложения, без push. Схема базы 4; перед обновлением сохранить копию остановленной базы. Подробности — [DIRECT_MESSAGES.md](docs/DIRECT_MESSAGES.md).

## Жалобы · 0.7

Жалобы на сообщения, собственные статусы, очередь модератора и журнал решений. [Поведение и назначение модератора](docs/MODERATION.md). Схема базы 5; перед обновлением сохранить копию остановленной базы. Реальные модераторы автоматически не назначаются.

## Результаты обращений · 0.8

Жалоба на первое сообщение доступна без принятия запроса. Индикатор «Жалобы» сообщает о новых решениях; их можно отметить прочитанными. История обращений догружается страницами. Схема базы 6; порядок резервного копирования — [MODERATION.md](docs/MODERATION.md).

```bash
npm run test:moderation-ui --prefix tests
```

## Апелляции · 0.9

Заявитель может один раз оспорить решение по жалобе. Пересмотр проводит другой модератор; оба решения сохраняются, результат пересмотра имеет отдельное уведомление. [Правила и ограничения](docs/MODERATION.md). Схема базы 7; перед обновлением нужна копия остановленной базы.

## Блокировки в общих чатах · 0.10

Можно заблокировать игрока из сообщения клуба. Его сообщения скрываются только у тебя; он остаётся в клубе. Снятие блокировки возвращает историю. Серверная фильтрация и защита от запоздавших ответов описаны в [CHAT.md](docs/CHAT.md). Схема базы 8; перед обновлением сохранить копию остановленной базы.

## Поиск напарников · 0.11

## Уведомления групп · 0.12

Личный список событий поиска напарников: заявки, решения, выход/исключение и закрытие группы. Счётчик непрочитанного обновляется раз в 5 секунд. Это уведомления внутри приложения, без push. [Описание](docs/LFG.md). Схема базы 10; перед обновлением сохранить копию остановленной базы.

## Полная локальная проверка

```bash
npm ci --prefix tests

```

[Отчёт по итоговой версии и оставшиеся проверки](docs/INTEGRATION_QA.md). DOM-тесты не заменяют визуальную проверку настоящим браузером.

### Автоматическая проверка и восстановление

Workflow `.github/workflows/verify.yml` запускает `npm run verify` на push и pull_request, включая черновые PR. Node закреплён на 24.19.0; Actions закреплены по SHA, доступ токена — только чтение содержимого. Результат выполнения смотреть в Checks конкретного commit; наличие workflow само по себе не означает успешный CI. Отдельный шаг запускает Chromium на ширинах 360/390/768/1440 px: основные экраны, чаты, группы и модерация. Это автоматические проверки сценариев и переполнения, не ручная визуальная приёмка.

Процедура холодной резервной копии и изолированного восстановления: [BACKUP.md](docs/BACKUP.md). Автоматическая тренировка входит в серверные тесты.

## Профили и изображения · 0.14

Ручные игровые поля, опциональный публичный профиль, отдельная видимость Riot ID, настоящие аватары и обложки, изображения в постах с серверным контролем доступа. Sharp используется для декодирования и перекодирования без исходных метаданных; перед локальным запуском выполнить `npm ci`. Схема SQLite 11: перед обновлением нужна холодная копия. [Описание и проверки](docs/PROFILES_MEDIA.md), [согласованный план развития](docs/ROADMAP.md).

## Поиск игроков · 0.15

«Найти команду → Игроки»: опубликованные профили, серверные фильтры роли/ранга/региона/языка/микрофона, поиск имени/логина. Из карточки можно открыть профиль или форму первого сообщения; отправка остаётся явным действием. В группах доступны фильтры ранга и голосовой связи. Схема базы остаётся 11. [Поведение и проверки](docs/PLAYER_FINDER.md).

## Обсуждения · 0.16

Реакции «Нравится / Полезно / Огонь», ответы с контекстом исходного комментария, @упоминания участников клуба и кнопка «Ответы», сохранённые публикации из профиля. Повтор отправки через текущий интерфейс не создаёт дубль. Закрытый контент и блокировки проверяются заново при каждом запросе. Миграция SQLite 11→12 выполняется под обслуживанием с холодной копией. [Поведение, API и проверки](docs/DISCUSSIONS.md).

## Развитие клубов · 0.17

Правила и метки, цветовой акцент, вкладки «Посты / Чат / Участники / Управление», до трёх закреплений, модераторы клуба, журнал действий. Владелец создаёт отзывные приглашения с лимитом и сроком; ссылка не обходит бан или подтверждение заявки. Передача владения требует согласия принятого участника. SQLite 12→13, холодная копия и проверка миграции до открытия трафика. [Права, API и проверки](docs/CLUB_MANAGEMENT.md).

## Игровые вечера · 0.18

Раздел «События»: организатор задаёт 2–5 мест по ролям и занимает своё, остальные игроки записываются сразу. Приватный чат доступен составу. Миграция 13→14 без удаления прежних данных; подробности и ограничения — [EVENTS.md](docs/EVENTS.md).

## Личная главная · 0.19

Для вошедшего игрока главная показывает текущие членства, ближайшие игры и подходящие свободные группы. Подбор по ручным полям профиля, без Riot API и вымышленной статистики. Схема остаётся 14. Подробности — [PERSONAL_HOME.md](docs/PERSONAL_HOME.md).

## Редактор публикаций · 0.20

Серверный черновик на клуб/автора, автоматическое и ручное сохранение, список в профиле, восстановление в новом сеансе и безопасный предпросмотр. Проверка версии защищает от перезаписи из другой вкладки. Публикация переносит вложение и удаляет черновик атомарно. Схема 14→15; подробности — [POST_EDITOR.md](docs/POST_EDITOR.md).

## Управление публикациями · 0.21

Редактирование заголовка/текста автором при активном членстве, отметка «Изменено», конфликт версий и безопасный повтор. Поиск по доступным опубликованным заголовкам/тексту с фильтром клуба и пагинацией. Схема 15→16; холодная копия перед обновлением. [Описание](docs/POST_MANAGEMENT.md).

## Опросы в клубах · 0.22

Публикация вопроса с 2–6 вариантами и сроком 1–168 часов; один неизменяемый голос участника, проценты и свой выбор без имён голосовавших. Повторы создания/голоса безопасны; завершение и права проверяются сервером. Схема 16→17, холодная копия перед обновлением. [Поведение и проверки](docs/POLLS.md).

## Руководства игроков · 0.23

Текст до 12 000 символов, краткое описание, тема, чемпион и версия игры, указанная автором. Каталог с поиском и фильтрами, предпросмотр и редактирование с защитой от конфликтов. Доступ клуба и блокировки проверяются сервером. Схема 17→18; [поведение и ограничения](docs/GUIDES.md).

Подготовлены одноразовые резервные коды без почты: генерация в профиле с текущим паролем, восстановление с отзывом всех сеансов. [Правила и миграция 18→19](docs/ACCOUNT_RECOVERY.md).
