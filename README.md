# Сообщество игроков Wild Rift

Статус: проектирование, версия документации 0.1 от 28 сентября 2026 года.
Название продукта пока не выбрано. Репозиторий: `lolokeksu09/wild-rift-community`, приватный, основная ветка `main`. Это отдельный проект, не RiftCore.

Социальная платформа по духу Amino: профили, публикации, клубы, чаты и поиск компании для Wild Rift. Главный сценарий: найти свой клуб, познакомиться и сыграть вместе.

## С чего начать

1. Прочитать [ТЗ](docs/SPEC.md) и [план](docs/ROADMAP.md).
2. Открыть `docs/prototype.html` в браузере: это автономный прототип с демонстрационными данными. Посты, комментарии, членство, заявки и сообщения сохраняются только в этом браузере.
3. Зафиксировать решения из [DECISIONS.md](docs/DECISIONS.md).
4. Выбрать следующую задачу в [GitHub Issues](https://github.com/lolokeksu09/wild-rift-community/issues).
5. Реализовать один сквозной сценарий по плану, затем провести закрытый пилот.

## Проверка прототипа v0.2

См. [отчёт о проверках](docs/PROTOTYPE_QA.md). Для DOM-тестов:

```bash
npm ci --prefix tests
npm test --prefix tests
```

Нужна версия Node, указанная в tests/package.json. Эти зависимости нужны только для тестирования; HTML открывается самостоятельно и не загружает внешние ресурсы. DOM-тесты не заменяют визуальную проверку в браузере.

## Локальная серверная версия 0.3

Нужен Node.js 24.19.x или более новая версия 24.x. В папке репозитория:

```bash
npm start
```

Открыть адрес из вывода (по умолчанию `http://127.0.0.1:3000`). Устанавливать runtime-зависимости не нужно. Сервер слушает только локальный интерфейс. Это отдельный работающий клиент; `docs/prototype.html` остаётся автономным дизайн-прототипом.

```bash
npm test
```

См. [SERVER.md](docs/SERVER.md) — запуск, ограничения и API; [отчёт](docs/SERVER_QA.md) — выполненные проверки.

## Чат клуба · 0.4

В серверном клиенте появилась общая комната каждого клуба. Сообщения хранятся в SQLite, новые загружаются опросом раз в две секунды. Даже в открытом клубе чат доступен только участникам. Повтор отправки использует тот же идентификатор и не создаёт дубль.

[Поведение, миграция и проверки](docs/CHAT.md). Перед первым запуском 0.4 поверх 0.3 остановить сервер и скопировать каталог базы: схема обновится с 1 до 2. Сервер остаётся локальным. Личные чаты добавлены следующим этапом 0.5.

```bash
npm run test:chat-ui --prefix tests
```

## Личные сообщения · 0.5

Запрос первого сообщения, принятие/отклонение, личная переписка, настройка запросов и блокировка доступны во вкладке «Сообщения». [Поведение, миграция 2→3 и проверки](docs/DIRECT_MESSAGES.md).

```bash
npm run test:direct-ui --prefix tests
```

## Непрочитанное · 0.6

В личных беседах доступны счётчики входящих сообщений и кнопка отметки прочтения. Навигация показывает непрочитанное и входящие запросы, обновляясь раз в 5 секунд. Это уведомления внутри приложения, без push. Схема базы 4; перед обновлением сохранить копию остановленной базы. Подробности — [DIRECT_MESSAGES.md](docs/DIRECT_MESSAGES.md).

## Жалобы · 0.7

Жалобы на сообщения, собственные статусы, очередь модератора и журнал решений. [Поведение и назначение модератора](docs/MODERATION.md). Схема базы 5; перед обновлением сохранить копию остановленной базы. Реальные модераторы автоматически не назначаются.

## Результаты обращений · 0.8

Жалоба на первое сообщение доступна без принятия запроса. Индикатор «Жалобы» сообщает о новых решениях; их можно отметить прочитанными. История обращений догружается страницами. Схема базы 6; порядок резервного копирования — [MODERATION.md](docs/MODERATION.md).

```bash
npm run test:moderation-ui --prefix tests
```

## Апелляции · 0.9

Заявитель может один раз оспорить решение по жалобе. Пересмотр проводит другой модератор; оба решения сохраняются, результат пересмотра имеет отдельное уведомление. [Правила и ограничения](docs/MODERATION.md). Схема базы 7; перед обновлением нужна копия остановленной базы.
